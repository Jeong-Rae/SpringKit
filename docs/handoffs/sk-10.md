# sk-10 handoff

## 배경

PR #8의 `finish`는 GitHub 병합을 완료한 뒤 로컬 `develop` 전환에 실패했습니다. `develop`이 다른 worktree에 체크아웃된 상태를 처리하지 못했고, 재실행할 때는 이미 병합된 PR과 로컬 추가 커밋을 구분하지 못했습니다.

## 변경 사항

- `finish`를 명시적인 상태 머신으로 구성했습니다.
- 원격 변경 전 사전 검사에서 worktree, 브랜치 HEAD, Gradle wrapper를 검증합니다.
- 루트에 Gradle wrapper가 없으면 저장소에서 추적하는 각 Gradle 프로젝트를 빌드합니다.
- 결과를 `FAILED`, `RECOVERY_REQUIRED`, `SUCCEEDED`로 구분합니다.
- 병합 요청의 응답이 실패해도 PR 상태를 다시 조회해 실제 병합 여부를 확인합니다.
- `SUCCEEDED`는 `develop` 동기화, Gradle build, 원격과 로컬 feature 브랜치 정리, 사후 검증이 모두 끝난 경우에만 반환합니다.
- 예외는 상태, 단계, 원인, 복구 방법으로 구성된 payload만 출력합니다. 스택 트레이스는 출력하지 않습니다.

GitHub 병합과 로컬 Git 작업은 하나의 트랜잭션으로 묶을 수 없습니다. 병합 이후 로컬 작업이 실패하면 `RECOVERY_REQUIRED`를 반환하며, 같은 `finish` 명령을 다시 실행하면 남은 단계부터 완료할 수 있습니다.

## 검증

```sh
kotlin scripts/git/git-workflow-worktree.test.main.kts
```

테스트는 다음 경로를 검증합니다.

- 사전 검사 실패 시 병합 명령을 호출하지 않음
- 병합 후 build 실패 시 feature 브랜치를 보존하고 `RECOVERY_REQUIRED` 반환
- 재실행 시 `develop` 동기화, build, 브랜치 정리 완료
- 일반 오류와 상태 머신 오류에서 스택 트레이스를 출력하지 않음
