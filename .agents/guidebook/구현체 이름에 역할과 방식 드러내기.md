# 구현체 이름에 역할과 방식 드러내기

인터페이스에는 맡은 역할을, 구현체에는 실제 구현 방식이나 더 좁은 역할을 이름으로 드러냅니다. 인터페이스임을 나타내는 `I`와 구현체임을 나타내는 `Impl`은 붙이지 않습니다.

## 인터페이스 이름을 정할 때

### 작성 지침

인터페이스가 제공하는 역할을 이름으로 표현합니다.

### Do Not 예시

```kotlin
interface IPaymentService // Do Not: I는 인터페이스라는 사실만 표시
```

### Do 예시

```kotlin
interface PaymentService // Do: 결제 서비스라는 역할을 표시
```

## 서비스 구현체 이름을 정할 때

### 작성 지침

서비스가 따르는 실제 업무 방식을 이름에 담습니다.

### Do Not 예시

```kotlin
class PaymentServiceImpl : PaymentService // Do Not: Impl로는 어떤 방식인지 알 수 없음
```

### Do 예시

```kotlin
class StandardPaymentService : PaymentService // Do: 표준 결제 방식을 표시
```

## 전략 구현체 이름을 정할 때

### 작성 지침

전략의 적용 대상이나 동작을 이름에 담아 다른 전략과 구분합니다.

### Do Not 예시

```kotlin
class PaymentStrategyImpl : PaymentStrategy // Do Not: Impl로는 어떤 결제 전략인지 알 수 없음
```

### Do 예시

```kotlin
class CardPaymentStrategy : PaymentStrategy // Do: 카드 결제 전략을 표시
```

## 저장소 구현체 이름을 정할 때

### 작성 지침

저장소가 사용하는 실제 기술이나 저장 방식을 이름에 담습니다.

### Do Not 예시

```kotlin
class PaymentRepositoryImpl : PaymentRepository // Do Not: Impl로는 저장 방식을 알 수 없음
```

### Do 예시

```kotlin
class JpaPaymentRepository : PaymentRepository // Do: JPA 저장 방식을 표시
class InMemoryPaymentRepository : PaymentRepository // Do: 메모리 저장 방식을 표시
```
