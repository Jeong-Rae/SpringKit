# 구현체 이름에 역할과 방식 드러내기

인터페이스와 구현체에 이름을 붙일 때는 각각의 역할과 실제 동작을 드러냅니다.

## 작성 지침

인터페이스에는 맡은 역할을, 구현체에는 실제 구현 방식이나 더 좁은 역할을 이름으로 표현합니다. 클래스를 상속할 때도 같은 기준을 적용합니다. 인터페이스임을 나타내는 `I`와 구현체임을 나타내는 `Impl`은 붙이지 않습니다.

## Do Not 예시

```kotlin
interface IPaymentService // Do Not: I는 인터페이스라는 사실만 표시

class PaymentServiceImpl : PaymentService // Do Not: 서비스의 업무 방식이 드러나지 않음

class PaymentRepositoryImpl : PaymentRepository // Do Not: 저장 방식을 알 수 없음

class NotificationSenderImpl : NotificationSender // Do Not: 알림 전송 채널이 드러나지 않음

class LoginStrategyImpl : LoginStrategy // Do Not: 로그인 인증 방식이 드러나지 않음

class UserDetailsImpl : UserDetails // Do Not: 인증 주체의 역할이 드러나지 않음

class PaymentHandlerImpl : PaymentHandler() // Do Not: 상속한 클래스 이름만 반복
```

## Do 예시

```kotlin
interface PaymentService // Do: 결제 서비스라는 역할을 표시

class StandardPaymentService : PaymentService // Do: 표준 결제 방식을 표시

class JpaPaymentRepository : PaymentRepository // Do: JPA 저장 방식을 표시
class InMemoryPaymentRepository : PaymentRepository // Do: 메모리 저장 방식을 표시

class EmailSender : NotificationSender // Do: 이메일 알림 전송 채널을 표시
class PushSender : NotificationSender // Do: 푸시 알림 전송 채널을 표시

class EasyAuthenticator : LoginStrategy // Do: 간편 인증 방식을 표시
class JointCertificateAuthenticator : LoginStrategy // Do: 공동인증서 인증 방식을 표시

class AuthenticatedPrincipal : UserDetails // Do: 인증된 주체라는 좁은 역할을 표시

class CardPaymentHandler : PaymentHandler() // Do: 카드 결제 처리 역할을 표시
```
