# 의존성 경계와 확인된 확장 지점만 추상화하기

추상화는 의존성 방향을 분리하거나 요구사항에서 확인된 변형을 수용할 때 사용합니다.

## 작성 지침

의존성 경계를 만드는 추상화는 구현체 수와 관계없이 사용할 수 있습니다. 도메인이나 애플리케이션이 인프라의 구체적인 기술에 의존하지 않도록 정의한 인터페이스가 이에 해당합니다.

의존성 경계 내부의 구현 요소는 구현체가 하나로 예상된다면 미래의 가능성만으로 인터페이스나 추상 클래스를 분리하지 않습니다. 기획이나 요구사항에서 서로 다른 구현, 정책, 전략이 구체적으로 예정되어 있을 때 확장 지점을 만듭니다.

확장이 필요하더라도 상속 계층을 먼저 만들지 않습니다. 변경되는 역할을 별도의 객체로 분리하고 `has-a` 조합 관계로 구성할 수 있는지 우선 고려합니다. 상속은 하위 타입이 상위 타입의 계약과 의미를 그대로 만족하는 `is-a` 관계가 명확할 때 사용합니다.

## Do Not 예시

```kotlin
interface StockOrderNumberGenerator { // Do Not: 예정되지 않은 단일 구현의 확장 지점
    fun generate(): StockOrderNumber
}

class UuidStockOrderNumberGenerator : StockOrderNumberGenerator {
    override fun generate(): StockOrderNumber = ...
}

class JpaStockOrderRepository :
    QuerydslRepositorySupport(StockOrderJpaEntity::class.java),
    StockOrderRepository { // Do Not: 조회 기술 재사용을 상속 계층에 결합

    ...
}
```

## Do 예시

```kotlin
class StockOrderNumberGenerator { // Do: 현재 요구되는 단일 구현
    fun generate(): StockOrderNumber = ...
}

interface CommissionPolicy { // Do: 기획에서 확인된 정책 확장
    fun calculate(order: StockOrder): Money
}

class DomesticStockCommissionPolicy : CommissionPolicy // Do: 국내주식 수수료 정책
class OverseasStockCommissionPolicy : CommissionPolicy // Do: 해외주식 수수료 정책

interface StockOrderRepository { // Do: 애플리케이션과 영속성 기술의 의존성 경계
    fun save(order: StockOrder): StockOrder
    fun openOrders(accountId: AccountId): List<StockOrder>
}

interface SpringDataJpaStockOrderRepository :
    JpaRepository<StockOrderJpaEntity, Long>

class QuerydslStockOrderQuery(
    private val queryFactory: JPAQueryFactory,
) {
    fun openOrders(accountId: AccountId): List<StockOrderJpaEntity> = ...
}

class JpaStockOrderRepository(
    private val springDataRepository: SpringDataJpaStockOrderRepository,
    private val orderQuery: QuerydslStockOrderQuery,
) : StockOrderRepository { // Do: 인프라 기능 조합으로 경계 계약 구현

    override fun save(order: StockOrder): StockOrder = ...

    override fun openOrders(accountId: AccountId): List<StockOrder> = ...
}
```
