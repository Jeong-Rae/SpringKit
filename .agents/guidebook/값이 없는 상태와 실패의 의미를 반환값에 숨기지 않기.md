# 값이 없는 상태와 실패의 의미를 반환값에 숨기지 않기

호출자는 `null`, `Optional`, 특수 반환값에 담긴 별도의 규칙을 해석하지 않고 결과를 사용할 수 있어야 합니다.

## 작성 지침

값이 없는 상태나 실패를 `null`, `Optional`, `-1`, 빈 문자열처럼 호출자가 별도로 해석해야 하는 반환값으로 표현하지 않습니다. 피호출자가 자신의 작업 범위에서 의미를 판단할 수 있다면 내부에서 처리하고 명확한 값이나 호출자가 처리할 수 있는 예외를 제공합니다.

외부 라이브러리나 Spring Data Repository가 `Optional`이나 nullable 값을 반환하더라도 해당 계약은 가능한 한 이를 조합하는 구현 내부에서 처리합니다. 호출자가 외부 의존성의 반환 규칙까지 알 필요가 없도록 합니다.

기본 동작만으로 값을 확정할 수 없고 호출 상황에 따라 복구 방법이 달라진다면 호출자가 복구 방법만 선택할 수 있는 옵션을 제공합니다. 옵션에는 기본 동작을 두고, 값이 없는지 확인하거나 복구 작업을 실행한 뒤 다시 조회하는 제어 흐름은 피호출자가 처리합니다. 같은 설정을 여러 작업에 적용해야 한다면 기본값이 있는 빌더 체이닝으로 제공할 수 있습니다.

피호출자에서 처리하면 책임 범위가 지나치게 넓어지거나 구현 복잡도가 크게 증가하는 경우에는 호출자가 값을 직접 확인하고 처리할 수 있습니다. 이 경우 `/** ... */` 형식의 KDoc에 값이 없는 상태가 발생하는 배경, 현재 호출에서의 의미, 내부에서 해결하지 않은 이유, 해결 방법을 작성합니다. 판단에 필요한 내부 코드나 외부 문서도 함께 링크합니다.

값이 없는 상태를 처리한 뒤에는 같은 의미를 nullable 값이나 다른 특수 반환값으로 다시 전달하지 않습니다.

## Do Not 예시

```kotlin
interface MarketSessionRepository {

    fun findByDate(date: LocalDate): MarketSession? // Do Not: 호출자가 null의 의미를 해석

    fun findCurrent(): Optional<MarketSession> // Do Not: Optional로 같은 책임을 전달
}

fun findMarketCode(exchange: Exchange): Int =
    repository.findMarketCode(exchange) ?: -1 // Do Not: -1에 값이 없는 상태를 숨김
```

```kotlin
fun openMarket(date: LocalDate) {
    val session = marketSessionRepository.findByDate(date)

    if (session == null) {
        marketCalendarSynchronizer.synchronize(date)

        val synchronized = marketSessionRepository.findByDate(date)

        if (synchronized != null) {
            open(synchronized)
        }
    } // Do Not: 호출자가 확인, 복구, 재조회까지 직접 제어
}
```

## Do 예시

피호출자가 처리할 수 있다면 외부 의존성의 반환 규칙을 내부에서 해결합니다.

```kotlin
class JpaMarketSessionRepository(
    private val repository: SpringDataJpaMarketSessionRepository,
) : MarketSessionRepository {

    override fun findByDate(date: LocalDate): MarketSession =
        repository.findByDate(date)
            .map(MarketSessionJpaEntity::toDomain)
            .orElseThrow {
                MarketSessionNotFoundException(date)
            }
}
```

복구 방법이 호출 상황에 따라 달라진다면 호출자는 복구 방법만 선택합니다.

```kotlin
fun findByDate(
    date: LocalDate,
    whenMissing: () -> Unit = {},
): MarketSession {
    val session = repository.findByDate(date)

    if (session.isPresent) {
        return session.get().toDomain()
    }

    whenMissing()

    return repository.findByDate(date)
        .map(MarketSessionJpaEntity::toDomain)
        .orElseThrow {
            MarketSessionNotFoundException(date)
        }
}
```

기본 동작에는 별도의 설정이 필요하지 않습니다.

```kotlin
val session = marketSessionRepository.findByDate(today)
```

외부 장 정보와 동기화가 필요한 호출에서만 복구 방법을 지정합니다.

```kotlin
val session = marketSessionRepository.findByDate(today) {
    marketCalendarSynchronizer.synchronize(today)
}
```

피호출자에서 합리적으로 해결하기 어려운 경우에는 호출자가 직접 처리하고 판단 근거를 KDoc으로 남깁니다.

```kotlin
/**
 * 거래소는 장 개시 직후 실시간 시세가 형성되기 전까지 null을 반환할 수 있다.
 *
 * 시세가 없는 이유는 호출 상황에 따라 달라 이 클라이언트에서 하나의 동작으로
 * 처리하지 않는다. 현재 주문 가격 계산에서는 실시간 시세가 없으면 최근 확정
 * 종가를 사용한다.
 *
 * 참고: [거래소 실시간 시세 조회 정책](https://docs.example.com/market/quote)
 */
fun calculatePrice(symbol: Symbol): Price {
    val quote = exchangeClient.findBySymbol(symbol)

    if (quote == null) {
        return closingPriceRepository.findLatestBySymbol(symbol)
    }

    return quote.price()
}
```
