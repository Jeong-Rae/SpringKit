예외는 호출자의 대응 방법에 따라 구분합니다

예외가 어디에서 발생했는지만으로 예외 타입을 설계하지 않습니다.

호출자가 실패를 확인했을 때 어떤 대응을 할 수 있는지를 기준으로 예외를 구분합니다.

Not:

DatabaseException
RedisException
HttpException

이 이름은 실패가 발생한 기술적 위치를 설명하지만 호출자가 어떻게 대응해야 하는지는 설명하지 않습니다.

호출자가 다시 시도할 수 있는 실패라면 재시도 가능성을 표현합니다.

class RetryableGameException(
    cause: Throwable,
) : RuntimeException(cause)

요청 자체가 거절되어 입력이나 상태를 변경해야 한다면 별도의 의미를 표현합니다.

class BetRejectedException : RuntimeException()

현재 게임을 계속 진행할 수 없다면 해당 대응 가능성을 표현합니다.

class GameUnavailableException(
    cause: Throwable,
) : RuntimeException(cause)

예외 타입을 읽었을 때 호출자가 취할 수 있는 대응을 판단할 수 있어야 합니다.

하위 계층의 기술적인 발생 원인은 로그와 cause로 보존할 수 있습니다. 공개되는 예외 계약은 호출자의 대응 방식에 맞춰 설계합니다.
