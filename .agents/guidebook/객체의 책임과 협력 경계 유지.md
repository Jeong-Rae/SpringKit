# 객체의 책임과 협력 경계 유지

객체가 자신의 데이터를 사용하는 판단과 행동을 맡고, 호출자는 협력 객체의 내부 구조에 의존하지 않도록 설계합니다.

TDA는 판단과 행동의 책임을 어디에 둘지, 디미터 법칙은 누구와 협력할지를 다룹니다. 두 원칙은 서로 다른 기준이므로 각각 검토합니다.

## TDA

TDA(Tell Don't Ask)는 객체의 데이터를 꺼내 외부에서 판단하고 처리하기보다 객체에 필요한 행동을 요청하는 원칙입니다.

### 작성 지침

함께 바뀌는 데이터와 판단 규칙을 같은 객체에 배치합니다. 호출자는 필요한 작업을 요청하고, 객체는 자신의 규칙에 따라 판단하고 처리합니다.

객체의 판단 규칙을 호출자가 대신 수행하는지 확인합니다. 책임에 맞는 판단 결과나 정보는 조회할 수 있습니다.

계층별 책임도 함께 고려합니다. 행동을 옮길 때는 데이터를 보유한 객체가 해당 행동을 맡아야 하는지 판단합니다.

### Do Not 예시

```kotlin
class SecuritiesAccount(
    availableOrderAmount: Long,
) {
    var availableOrderAmount: Long = availableOrderAmount
        private set

    fun reserveForBuyOrder(amount: Long) {
        availableOrderAmount -= amount
    }
}

require(orderAmount > 0) // Do Not: 주문 금액 검증을 호출자가 수행
require(orderAmount <= account.availableOrderAmount) // Do Not: 계좌의 주문 가능 금액을 꺼내 예약 가능 여부 판단
account.reserveForBuyOrder(orderAmount) // Do Not: 계좌의 규칙 준수가 호출자의 사전 검증에 의존
```

```kotlin
class SecuritiesAccount(
    private val availableOrderAmount: Long,
) {
    fun showOrderableAmount(screen: OrderScreen) { // Do Not: 조회를 피하려고 화면 표시 책임까지 계좌에 배치
        screen.showOrderableAmount(availableOrderAmount)
    }
}

account.showOrderableAmount(screen)
```

### Do 예시

```kotlin
class SecuritiesAccount(
    availableOrderAmount: Long,
) {
    private var availableOrderAmount: Long = availableOrderAmount

    fun reserveForBuyOrder(amount: Long) {
        require(amount > 0) // Do: 계좌가 예약할 주문 금액 검증
        require(amount <= availableOrderAmount) // Do: 데이터를 보유한 계좌가 예약 가능 여부 판단
        availableOrderAmount -= amount // Do: 계좌가 검증한 금액 예약
    }

    fun orderableAmount(): Long =
        availableOrderAmount // Do: 화면 표시에 필요한 정보를 조회로 제공
}

account.reserveForBuyOrder(orderAmount) // Do: 호출자는 계좌에 매수 주문 금액 예약 요청
```

```kotlin
screen.showOrderableAmount(account.orderableAmount()) // Do: 계좌의 정보를 조회하고 화면 표시는 화면 객체가 담당
```

## Law of Demeter

디미터 법칙(Law of Demeter)은 객체가 직접 알고 있는 가까운 객체와만 협력하도록 제한하는 원칙입니다. 다른 객체의 내부 객체까지 탐색하지 않도록 하여 내부 구조에 대한 의존을 줄입니다.

### 작성 지침

자신, 직접 보유한 객체, 전달받은 객체, 직접 생성한 객체와 협력합니다. 다른 객체에서 내부 객체를 꺼내 그 내부로 들어가는 호출 대신 가까운 협력 객체에 필요한 행동을 요청합니다.

위임할 행동은 협력 객체의 책임에 맞게 구성합니다. 내부 객체를 그대로 노출하기보다 호출 목적을 표현하는 행동을 제공합니다. 내부 행동은 해당 객체가 직접 수행하거나 위임합니다.

점의 개수보다 호출자가 다른 객체의 내부 구조를 알아야 하는지 확인합니다. 호출을 여러 줄이나 지역 변수로 나누어도 내부 구조에 대한 의존은 남습니다.

판단 결과를 조회할 때도 같은 협력 범위를 적용합니다. 가까운 객체가 내부에서 판단한 결과를 제공하도록 구성합니다.

### Do Not 예시

```kotlin
val canReserve = account.cashBalance.canReserve(orderAmount) // Do Not: 계좌의 내부 객체를 꺼내 직접 협력
```

```kotlin
val cashBalance = account.cashBalance // Do Not: 지역 변수로 나누어도 계좌의 내부 구조에 의존
val canReserve = cashBalance.canReserve(orderAmount) // Do Not: 꺼낸 내부 객체와 직접 협력
```

```kotlin
class BuyOrderService(
    private val auditLog: OrderAuditLog,
) {
    fun reserve(session: TradingSession, amount: Long) {
        session.account.reserveForBuyOrder(amount) // Do Not: 세션에서 내부 계좌를 찾아 주문 금액 예약
        val event = BuyOrderReserved(amount)
        auditLog.record(event.description())
    }
}
```

### Do 예시

```kotlin
class SecuritiesAccount(
    private val cashBalance: CashBalance,
) {
    fun canReserveForBuyOrder(amount: Long): Boolean =
        cashBalance.canReserve(amount) // Do: 직접 보유한 객체에 예약 가능 여부 판단 위임
}

class CashBalance(
    private val availableOrderAmount: Long,
) {
    fun canReserve(amount: Long): Boolean =
        amount > 0 && amount <= availableOrderAmount
}

val canReserve = account.canReserveForBuyOrder(orderAmount) // Do: 내부 구조를 탐색하지 않고 계좌에 판단 결과 조회
```

```kotlin
class BuyOrderService(
    private val auditLog: OrderAuditLog,
) {
    fun reserve(account: SecuritiesAccount, amount: Long) {
        account.reserveForBuyOrder(amount) // Do: 전달받은 객체에 필요한 행동 요청
        val event = BuyOrderReserved(amount)
        val description = event.description() // Do: 직접 생성한 객체와 협력
        record(description) // Do: 자신의 함수 호출
    }

    private fun record(description: String) {
        auditLog.record(description) // Do: 직접 보유한 객체에 기록 요청
    }
}
```
