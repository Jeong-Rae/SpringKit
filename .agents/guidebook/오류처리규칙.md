오류 코드를 반환하지 않습니다

실패를 숫자, 문자열 또는 상태 코드로 반환하고 호출자가 그 값을 해석하도록 만들지 않습니다.

Not:

fun placeBet(
    player: Player,
    bet: Bet,
): Int {
    if (!bet.isPositive()) {
        return -1
    }

    if (!player.canBet(bet)) {
        return -2
    }

    player.placeBet(bet)
    return 0
}

Do:

fun placeBet(
    player: Player,
    bet: Bet,
) {
    if (!bet.isPositive()) {
        throw BetRejectedException()
    }

    if (!player.canBet(bet)) {
        throw BetRejectedException()
    }

    player.placeBet(bet)
}

정상 흐름은 정상 동작만 표현하고, 실패 흐름은 예외로 분리합니다.

Unchecked 예외를 사용합니다

Kotlin에서는 Java와 같은 Checked Exception 검사가 적용되지 않습니다. 애플리케이션의 오류 계약도 호출자에게 try-catch를 문법적으로 강제하는 방식보다 Unchecked Exception을 기준으로 설계합니다.

Java 라이브러리와 연동하면서 Checked Exception이 발생한다면 구현 세부 사항을 상위 계층까지 그대로 전파하지 않습니다. 필요한 경계에서 시스템의 의미에 맞는 예외로 변환합니다.

Not:

fun loadGame(id: GameId): Game {
    return jdbcGameRepository.load(id)
}

하위 기술에서 발생한 예외가 애플리케이션 전체에 그대로 노출될 수 있습니다.

Do:

fun loadGame(id: GameId): Game {
    try {
        return gameRepository.load(id)
    } catch (exception: SQLException) {
        throw GameUnavailableException(
            cause = exception,
        )
    }
}

외부 기술의 예외를 변환할 때 원래 예외는 cause로 보존하여 진단 정보를 잃지 않습니다.
