# 필요성 (NEC)

현재 요구의 수용 조건과 최소 구현 범위를 결정할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| NEC-01 | 무엇을 관찰하면 완료되었다고 판단할 수 있는가? | 요구 동작과 확인된 수용 조건을 작업 경계로 확정합니다. |
| NEC-02 | 현재 후보가 실제로 충족하지 못한 조건은 무엇인가? | 해당 조건을 충족하는 데 필요한 범위만 확장합니다. |
| NEC-03 | 의도적인 단축 구현이 허용되는 실제 한계는 무엇인가? | 단축의 한계와 재검토 조건을 추적할 수 있게 남깁니다. |

## 규칙 실행 계약

### NEC-01 - 요구와 작업 경계

- **적용 조건:** Editing 또는 Fixing 작업을 시작합니다.
- **수행 행동:** 요청을 관찰 가능한 동작/수용 조건으로 정리합니다. 관련 호출자 계약과 실제 운영 제약을 확인하고, 하나의 요청에 포함된 필수 동작을 모두 작업 범위에 포함합니다.
- **판단 증거:** 사용자 요구, 기존 코드/계약, 재현 가능한 기대 결과와 운영 설정.
- **다음 전이:** 조건이 확인되면 Editing의 최소 후보 탐색 또는 Fixing의 원인 조사로 진행합니다. 필수 계약이 불명확하면 필요한 부분을 추가 확인합니다.

### NEC-02 - 미충족 조건에 따른 범위 확장

- **적용 조건:** Editing 후보가 수용 조건이나 필수 계약을 충족하지 못합니다. Fixing에서 선택한 클로저의 Editing 단계에도 적용합니다.
- **수행 행동:** 충족하지 못한 조건을 하나 이상 특정하고, 이를 해결할 행위/호출 경로/책임 범위만 추가하거나 변경 위치를 이동합니다. 이미 충족한 동작을 재구현하지 않습니다.
- **판단 증거:** 현재 후보와 요구 동작의 차이, 실패 사례, 계약을 소유한 객체/사용 경로.
- **다음 전이:** 미충족 조건이 남으면 해당 조건만큼 후보를 확장하고 다시 검증합니다. 모두 충족하면 `COM-01`의 완결성 확인으로 진행합니다.

### NEC-03 - 의도적 단축 구현

- **적용 조건:** 현재 운영 제약에서 일부 구현을 의도적으로 단축하기로 선택합니다.
- **수행 행동:** 유지되는 제한과 재검토 조건을 `shortcut: <한계>, <재검토 조건>`으로 기록합니다. 기존 안전성/데이터/호출자 계약을 보존합니다.
- **판단 증거:** 실제 처리량/배포 환경과 확인된 제한 조건.
- **다음 전이:** 제한이 현재 사용 조건과 일치하면 검증 단계로 진행합니다. 사용 조건이 제한을 벗어나면 구현 범위를 재검토합니다.

## 점진적 확장의 경계

점진적 확장은 구현 크기가 수치 순서로 정렬되었다는 가정을 사용하지 않습니다. 수정할 행위와 책임 위치를 함께 탐색합니다. 필요한 책임이 도메인 객체에 있다면 해당 객체에서의 변경을 검토합니다.

예: 기존 검색 화면의 날짜 조건에 필요한 입력을 현재 검색 컴포넌트가 이미 전달한다면 재사용합니다. 요구된 날짜 형식이 다르면 해당 차이만 수정합니다.
