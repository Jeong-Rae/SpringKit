# 필요성 (NEC)

현재 요구에서 가치를 전달하는 범위만 결정할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| NEC-01 | 완료되었다고 판단할 관찰 가능한 동작은 무엇인가? | 요구와 수용 조건을 현재 작업의 경계로 정합니다. |
| NEC-02 | 사용자 요청이나 확인된 제약 없이 추가하는 기능이 있는가? | 추측한 옵션·확장성·설정을 제거합니다. |
| NEC-03 | 지금 생략한 부분이 안전한 한계 안에 있는가? | 한계와 재검토 시점을 추적 가능하게 남깁니다. |

## 실행 지침

- **NEC-01:** 요청을 하나의 핵심 결과와 필요한 조건으로 정리합니다. 모호한 요청은 핵심 사용 사례가 작동하는 가장 작은 범위를 선택하고, 안전이나 계약을 좌우하는 모호함만 확인합니다.
- **NEC-02:** 새 기능·확장 포인트·설정이 필요한 현재 시나리오를 제시할 수 없다면 구현하지 않습니다. 불필요한 코드를 제거하는 대안도 검토합니다. 명시적으로 요구한 기능은 보존합니다.
- **NEC-03:** 현실적인 운영 범위에서는 허용되는 단축 구현만 선택합니다. 지속될 기술적 한계에는 `shortcut: <한계>, <재검토 조건>`을 남깁니다. 재검토 조건이 없는 막연한 TODO는 만들지 않습니다.

## 작업 범위의 판정 (NEC-01~03)

수용 조건은 현재 사용자가 요구한 동작과 확인된 프로젝트 제약으로 정의합니다. 하나의 요청에 서로 다른 필수 동작이 포함되어 있다면 모두 완결 대상입니다. 예상 사용량이나 미래 기능은 실제 근거가 없는 한 새로운 요구로 취급하지 않습니다.

예: 기존 화면에 검색 조건 하나를 추가하는 요청이라면 검색 결과와 기존 동작의 보존이 수용 조건입니다. 사용자가 요청하지 않은 검색 조건 편집기나 플러그인 구조는 추가하지 않습니다.
