# 필요성 (NEC)

현재 요구의 수용 조건과 최소 구현 범위를 결정할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| NEC-01 | 무엇을 관찰하면 완료되었다고 판단할 수 있는가? | 요구 동작과 확인된 수용 조건을 작업 경계로 확정합니다. |
| NEC-02 | 현재 후보가 실제로 충족하지 못한 조건은 무엇인가? | 해당 조건을 충족하는 데 필요한 범위만 확장합니다. |
| NEC-03 | 의도적인 단축 구현이 허용되는 실제 한계는 무엇인가? | 단축의 한계와 재검토 조건을 추적할 수 있게 남깁니다. |

## 실행 지침

- **NEC-01:** 요청을 관찰 가능한 결과와 필요한 조건으로 정리합니다. 여러 필수 동작이 포함된 요청은 모두 수용 조건에 포함합니다. 기존 계약과 실제 운영 제약을 확인하며, 근거 없는 미래 요구를 추가하지 않습니다.
- **NEC-02:** Editing에서는 기존 동작으로 요구를 충족하는지 먼저 확인합니다. 후보가 충족하지 못하는 조건을 명시한 뒤 필요한 행위·호출 경로·책임 범위만 추가합니다. 조건이 충족되었다면 구현 범위 확장을 중단합니다.
- **NEC-03:** 확인한 운영 제약에서 허용되는 단축만 선택합니다. 유지되는 제한에는 `shortcut: <한계>, <재검토 조건>`을 남깁니다. 단축 구현으로 보안·데이터·호출자 계약을 생략하지 않습니다.

## 점진적 확장의 경계 (NEC-01, NEC-02)

점진적 확장은 기능 크기가 수치 순서로 정렬되었다는 가정을 사용하지 않습니다. 수정해야 하는 행위와 책임 위치를 함께 탐색합니다. 필요한 책임이 기존 도메인 객체에 있다면 호출부에 우회 코드를 쌓는 대신 해당 책임으로 변경 위치를 정합니다.

예: 검색 화면에 날짜 조건을 추가할 때 기존 검색 컴포넌트가 날짜 값을 전달한다면 해당 기능을 활용합니다. 필요한 계약 차이가 확인된 경우에만 해당 입력 부분을 수정합니다. 검색 조건 편집기나 설정 계층은 현재 요구가 있을 때 검토합니다.
