# 필요성 (NEC)

현재 요구의 수용 조건과 최소 유효 제어의 범위를 정할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| NEC-01 | 실제로 충족해야 하는 결과와 불변식은 무엇인가? | 기능/정합성/운영 계약을 현재 작업의 조건으로 확정합니다. |
| NEC-02 | 최소 유효 후보에서 충족하지 못한 조건은 무엇인가? | 그 조건을 충족하는 만큼만 책임과 제어를 확장합니다. |
| NEC-03 | 어떤 제한과 확인된 성능 문제를 현 범위에 보류하는가? | 사실 근거/범위/재검토 조건을 추적 가능하게 남깁니다. |

## 규칙 실행 계약

### NEC-01 - 요구와 작업 경계

- **적용 조건:** Editing 또는 Fixing 작업을 시작합니다.
- **수행 행동:** 관찰 가능한 요구와 수용 조건, 도메인 불변식, 기존 호출자/동시성/데이터 계약을 확인합니다. 격리 수준과 락 등의 제어가 결과에 필수인지 조사합니다. 명시된 성능 목표와 실제 운영 제약을 구분합니다.
- **판단 증거:** 사용자 요구, 기존 코드/설정/계약, 실제 실행 조건, 테스트와 확인된 불변식.
- **다음 전이:** 필수 조건이 확인되면 최소 유효 제어에서 Editing을 시작하거나 Fixing에서 원인을 조사합니다. 불명확한 필수 조건은 해당 계약을 추가 조사합니다.

### NEC-02 - 미충족 조건에 따른 범위 확장

- **적용 조건:** Editing 후보가 수용 조건, 도메인 불변식 또는 필수 실행 제어를 충족하지 못합니다. Fixing에서 선택된 클로저의 Editing에도 적용합니다.
- **수행 행동:** 미충족 조건을 특정하고 이를 충족할 최소 책임/실행 경계만 확장합니다. 동기/순차 실행으로 충족하면 더 많은 동시성이나 캐시를 추가하지 않습니다. 필요한 제어는 축소를 이유로 생략하지 않습니다.
- **판단 증거:** 현재 후보와 실제 계약의 차이, 실패/경쟁 재현, 쓰기와 상태 전이의 소유 책임.
- **다음 전이:** 미충족 조건이 남으면 해당 조건만큼 확장하고 다시 검증합니다. 모두 충족하면 `COM-01`로 진행합니다.

### NEC-03 - 단축 구현과 보류한 성능 문제

- **적용 조건:** 실제 운영 조건에서 의도적 단축을 선택하거나, 확인된 성능 문제가 현재 선택 범위를 넘어서는 도메인/JPA 재설계를 필요로 합니다.
- **수행 행동:** 허용된 단축에는 `shortcut: <한계>, <재검토 조건>`을 남깁니다. 범위 밖의 **확인된** 성능 문제에는 관련 코드의 정확한 위치에 `FIXME(perf)` 주석으로 관찰 증거/보류 범위/재검토 조건을 기록하고 작업 결과에도 명시합니다. 추측만으로 주석이나 수정 범위를 늘리지 않습니다.
- **판단 증거:** 재현 가능한 성능 수치/쿼리 로그/메모리 프로파일, 해당 코드 위치, 필수 성능 계약과 현재 승인된 작업 경계.
- **다음 전이:** 기능과 필수 성능 조건을 충족하면 범위 내 작업을 검증하고 보류 사항을 보고합니다. 필수 조건을 위반했다면 완료로 선언하지 않고 필요한 추가 범위를 사용자에게 제안합니다.

## 보류 주석의 작성 예

아래는 형식 예시입니다. 실제 코드에는 측정한 값과 근거의 위치를 적습니다. 관련 코드에 직접 주석을 남길 수 없으면 수정 가능한 가장 인접한 지점을 확인하고 작업 결과에 위치를 명시합니다.

```kotlin
// FIXME(perf): <관찰한 조회 경로>에서 <확인된 N+1/메모리 사용 문제>.
// 근거: <재현 테스트/쿼리 로그/프로파일링 결과의 위치>.
// 보류: <수정에 필요한 도메인 또는 JPA 경계, 현재 작업에서 제외한 범위>.
// 재검토: 후속 Fixing에서 작업 클로저 선택 후 수정.
```

이 주석은 해결된 문제에 남기지 않습니다. 보류된 문제가 현재 기능의 필수 조건을 위반하면 사용자 범위 결정 없이 완료할 수 없습니다.
