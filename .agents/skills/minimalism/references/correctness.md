# 정확성 (COR)

구현 범위를 줄이면서 기존 계약·안전성·실제 운영 조건을 보존할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COR-01 | 빈 값·잘못된 값·실패 상황에서 호출자는 어떻게 복구하는가? | 입력 경계와 복구 가능한 오류 계약을 유지합니다. |
| COR-02 | 변경이 인증·인가·데이터 보존에 영향을 주는가? | 필수 검증과 부작용의 원자성을 보존합니다. |
| COR-03 | 실제 사용량과 동시 실행에서 다른 결과가 발생하는가? | 현재 부하에 필요한 경쟁·메모리·조회 비용을 확인합니다. |
| COR-04 | 수정 전 문제를 재현하고 수정 후 회귀를 확인할 수 있는가? | Fixing의 재현 증거와 변경 후 검증을 구분합니다. |

## 실행 지침

- **COR-01:** 신뢰 경계의 입력을 검증하고 도메인 불변식은 해당 책임 객체에서 보장합니다. 경계값, 빈 값, 누락값, 시간·금액 계산과 실패 경로를 확인합니다. 예외는 호출자가 실제로 취할 수 있는 복구 전략을 기준으로 구분합니다.
- **COR-02:** 인증·인가·입력 검사·비밀정보 보호·데이터 쓰기의 순서와 트랜잭션을 생략하지 않습니다. 코드를 이동하거나 통합할 때도 기존 검증을 유지합니다.
- **COR-03:** 저장소의 배포·사용 방식에서 예상 부하를 확인합니다. 관련 코드의 경쟁 상태, 무제한 증가, N+1 조회와 대량 입력 비용을 검토합니다. 근거 없는 미래 규모를 위해 분산 계층을 도입하지 않습니다.
- **COR-04:** **Fixing의 조사 단계**에서는 재현 입력, 기대·실제 결과, 실패 테스트와 로그 등 확보한 증거를 기록합니다. **변경 이후**에는 해당 실패가 사라졌는지와 영향받는 계약을 검증합니다. Editing의 비자명한 분기·파서·상태 전이·금전·보안·데이터 변경에도 유의미한 테스트 또는 동등한 자체 검증을 남깁니다. 실행하지 않은 검증을 성공으로 표시하지 않습니다.

## Fixing의 증거와 검증 (COR-04)

재현을 확인했다는 사실과 원인 위치를 확정했다는 판단을 구별합니다. 원인과 수정 책임의 탐색은 [원인·클로저](location.md)의 `LOC-01`을 따릅니다. 수정 후에는 선택된 클로저의 재현 조건과 관련 호출 경로를 검증합니다.
