# 정확성 (COR)

현재 요구를 충족하면서 호출자 계약과 안전성, 실제 운영 조건을 보존할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COR-01 | 빈 값/잘못된 값/실패 상황에서 호출자는 어떻게 복구하는가? | 입력 경계와 복구 가능한 오류 계약을 유지합니다. |
| COR-02 | 변경이 인증/인가/데이터 보존에 영향을 주는가? | 필수 검증과 부작용의 원자성을 보존합니다. |
| COR-03 | 실제 사용량과 동시 실행에서 다른 결과가 발생하는가? | 현재 부하에 필요한 경쟁/메모리/조회 비용을 확인합니다. |
| COR-04 | 수정 전 문제를 재현하고 수정 후 회귀를 확인할 수 있는가? | Fixing 조사와 변경 후 검증, Editing의 비자명한 로직 검증을 수행합니다. |

## 규칙 실행 계약

### COR-01 - 입력/오류 계약

- **적용 조건:** 변경 대상이 외부 입력, 실패 처리 또는 호출자에게 전달하는 결과/예외를 다룹니다.
- **수행 행동:** 신뢰 경계의 입력을 검증하고 도메인 불변식은 책임 객체에서 보장합니다. 빈 값/경계값/누락값/시간/금액과 실패 경로를 확인하며 오류를 호출자의 실제 복구 방법을 기준으로 구분합니다.
- **판단 증거:** 입력 계약, 호출자의 복구 행동, 실패/경계 입력의 기대 결과와 기존 테스트.
- **다음 전이:** 호출자의 계약을 만족하면 해당 구현/검증으로 진행합니다. 충족하지 못한 입력 조건이 확인되면 그 조건을 `NEC-02`로 전달합니다.

### COR-02 - 보안/데이터 정합성

- **적용 조건:** 외부 입력, 인증/인가, 비밀정보 또는 데이터 쓰기 등의 부작용이 변경 대상에 있습니다.
- **수행 행동:** 인증/인가/입력 검사/비밀정보 보호, 데이터 쓰기의 순서와 트랜잭션을 확인합니다. 코드를 이동/통합하더라도 기존 검증과 원자성을 유지합니다.
- **판단 증거:** 신뢰 경계, 권한 검사 위치, 트랜잭션/쓰기 순서, 관련 실패 테스트.
- **다음 전이:** 기존 불변식이 유지되면 검증 단계로 진행합니다. 확인된 위반 사항은 해당 책임에서 수정합니다.

### COR-03 - 운영 규모와 동시성

- **적용 조건:** 변경이 예상 부하, 여러 실행 주체 또는 공유 상태의 동작에 영향을 줍니다.
- **수행 행동:** 저장소의 배포/사용 구성을 확인하고 경쟁 상태, 무제한 메모리 증가, N+1 조회, 대량 입력의 비용을 관련 경로에서 점검합니다. 확인된 규모에 필요한 수준으로 구현합니다.
- **판단 증거:** 실제 배포 구성/요청 규모, 공유 상태 접근 경로, 관련 성능/동시성 재현 결과.
- **다음 전이:** 요구된 운영 조건이 충족되면 검증과 완료 판정으로 진행합니다. 실패가 관찰되면 해당 조건을 구현 범위 판단에 반영합니다.

### COR-04 - 수정 전 증거와 변경 후 검증

- **적용 조건:** **Fixing의 원인 조사**, **Fixing 수정 이후**, 또는 **Editing에서 분기/파서/상태 전이/금전/보안/데이터 처리 등의 비자명한 로직을 변경**합니다.
- **수행 행동:** Fixing 조사에서는 재현 입력과 기대/실제 결과, 실패 테스트/로그 등 확보한 사실을 기록합니다. Fixing 수정 뒤에는 같은 재현 조건과 관련 계약을 검증합니다. Editing에서는 변경된 행위의 실패를 감지할 최소한의 유의미한 테스트 또는 동등한 자체 검증을 수행합니다. 프로젝트의 필수 검증도 실행합니다.
- **판단 증거:** 실행한 명령과 결과, 실패/성공 테스트, 재현 데이터, 영향받는 호출 경로의 실제 결과. 실행하지 못한 검증은 별도로 식별합니다.
- **다음 전이:** 재현 조사에서 확인한 사실은 `LOC-01`의 원인 판단에 사용합니다. 변경 후 미충족 조건이 있으면 Editing의 해당 후보/확장 단계로 복귀합니다. 검증 결과를 확인하면 `COM-01`/`COM-02`로 이동합니다.

## 재현과 원인 확인의 구분

재현을 확인했다는 사실과 원인 위치를 확인했다는 판단을 분리합니다. 원인/책임 위치 탐색은 [원인/클로저](location.md)의 `LOC-01`을 적용합니다. 검증 도구가 실행되지 않았다면 완료된 테스트로 보고하지 않습니다.
