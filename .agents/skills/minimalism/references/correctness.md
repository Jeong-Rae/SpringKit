# 정확성 (COR)

현재 요구와 시스템 계약을 충족하는 **최소 제어 수준**에서 정확성/데이터 정합성/실행 영향 범위를 관리합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COR-01 | 호출자가 어떤 오류를 구분하고 복구해야 하는가? | 필요한 입력/실패 계약과 응답 분기만 유지합니다. |
| COR-02 | 어떤 불변식에 원자성/격리/동시성 제어가 필수인가? | 최초 구현부터 최소 유효한 데이터/경쟁 제어를 포함합니다. |
| COR-03 | 확인된 성능/자원 문제는 어디에서 발생하는가? | N+1/메모리 버스트/캐시/트랜잭션 비용을 해당 경로에서 확인합니다. |
| COR-04 | 실제 동작/불변식과 부작용을 검증했는가? | 수정 전 재현과 변경 후 계약/회귀 검증을 구분합니다. |
| COR-05 | 실행 영향 범위가 현재 계약의 최소 유효 경계인가? | 필수 제어를 유지하면서 부작용과 실행 복잡성을 최소화합니다. |

## 규칙 실행 계약

### COR-01 - 입력/오류 계약

- **적용 조건:** 외부 입력, 실패 처리, 결과/예외/응답 분기를 변경합니다.
- **수행 행동:** 신뢰 경계의 값을 검증하고 도메인 불변식은 책임 객체에서 보장합니다. 호출자가 구별하여 처리할 수 있는 실패만 별도로 표현하고 기존 복구 계약을 유지합니다.
- **판단 증거:** 외부 입력/오류 계약, 호출자의 실제 복구 방법, 경계값과 실패 테스트.
- **다음 전이:** 필요한 실패가 표현되면 구현/검증으로 진행하고, 빠진 입력 조건이 있으면 `NEC-02`에 따라 확장합니다.

### COR-02 - 기능적 정합성에 필요한 제어

- **적용 조건:** 인증/인가, 데이터 쓰기, 여러 변경의 원자성, 동시 수정 또는 트랜잭션 격리/락이 결과의 정확성에 영향을 줍니다.
- **수행 행동:** 보호할 도메인 불변식을 확인하고 **처음부터** 충족하는 최소 유효 수단을 선택합니다. 기존 데이터베이스 제약, 원자적 조건부 갱신, 단일 트랜잭션 경계, 버전 기반 충돌 검사, 필요한 행의 락 또는 격리 수준 중 실제 계약에 맞는 방법을 검토합니다. 전체 시스템 락이나 모든 트랜잭션의 격리 수준 상향을 기본으로 삼지 않습니다. 인증/인가와 데이터 정합성을 보존합니다.
- **판단 증거:** 불변식/실제 쓰기 경로, 경합 또는 롤백 테스트, 관련 스키마 제약, 데이터베이스의 격리 의미와 기존 트랜잭션 범위.
- **다음 전이:** 필수 계약과 실패/충돌 처리까지 충족하면 `COR-05`의 실행 범위를 검토합니다. 불변식이 깨지는 후보는 제거하고 `NEC-02`로 돌아갑니다.

### COR-03 - 성능/자원 문제 확인

- **적용 조건:** 구현 대상 경로에서 실제 성능 문제, 예상 부하/메모리/조회 비용, 캐시 데이터 최신성 또는 장시간 트랜잭션 영향이 확인되거나 해당 조건이 필수 수용 기준입니다.
- **수행 행동:** 관련 경로의 쿼리 실행 횟수(N+1), 메모리 버스트, 캐시 적중/무효화, 트랜잭션 대기/잠금/지속 시간과 대량 입력 비용을 확인합니다. 프로젝트가 요구하는 처리량/지연/자원 한도와 비교합니다. 기능 계약을 위반하는 성능 문제와 필수 조건을 충족하는 범위의 개선 과제를 구분합니다.
- **판단 증거:** 재현 입력, SQL 로그/쿼리 수, 메모리 프로파일, 지연/잠금 관측, 캐시 최신성 검증, 명시된 수용 조건.
- **다음 전이:** 문제의 책임과 필수 여부가 확인되면 `COR-05`에서 최소 제어를 선택합니다. 추가 구조 변경이 선택 범위를 넘어설 때는 `NEC-03` 또는 `LOC-02`에 따라 기록/제안합니다.

### COR-04 - 수정 전 증거와 변경 후 검증

- **적용 조건:** Fixing의 원인 조사/수정 이후 또는 Editing에서 분기/상태 전이/금전/보안/동시성/데이터 처리를 포함한 비자명한 로직을 변경합니다.
- **수행 행동:** Fixing 조사에서는 재현 입력과 기대/실제 결과를 기록합니다. 수정 뒤에는 같은 조건과 관련 계약을 재검증합니다. Editing에서는 기능 결과, 실패 경로와 실제 부작용을 감지할 유의미한 테스트를 수행하고 프로젝트의 필수 검증도 실행합니다.
- **판단 증거:** 실행한 명령/결과, 재현/회귀 테스트, 확인한 데이터 변경/잠금/쿼리/자원 동작, 미실행 검증.
- **다음 전이:** 확인한 재현 사실을 `LOC-01`에 전달합니다. 미충족 조건은 Editing의 관련 후보로 복귀하고, 충족 결과는 `COM-01`/`COM-02`로 전달합니다.

### COR-05 - 실행 영향 범위 최소화

- **적용 조건:** 쓰기, 외부 호출, 실행 순서, 동시성/비동기화, 캐싱, 트랜잭션, 락, 재시도, 자원 사용 방식의 변경을 검토합니다.
- **수행 행동:** 요구된 기능/불변식/성능 조건을 충족하는 후보들에서 변경되는 부작용과 실행 제어 범위를 확인합니다. 동기/순차 처리, 기존 직접 조회와 좁은 트랜잭션 경계를 기본 후보로 삼되, 필수 정합성이 요구하는 잠금/격리/원자성은 처음부터 포함합니다. 명시되지 않은 처리량 개선만을 위해 캐시, 비동기화, 재시도나 전역 제어를 추가하지 않습니다. 확인된 성능 문제에는 View/Projection, 제한된 페이지/청크 조회 등 기존 도메인/JPA 책임을 보존하는 국소 방어를 검토합니다.
- **판단 증거:** 실행 순서/외부 호출/데이터 쓰기 경로, 메모리/쿼리/락 영향, 부작용 재현과 실제 수용 조건.
- **다음 전이:** 필수 계약을 만족하면 국소 구현/검증을 진행합니다. 도메인/JPA 재설계가 필요한 확인된 문제는 현재 범위 밖일 때 `NEC-03`으로 기록하고 후속 Fixing 클로저에서 제안합니다. 필수 조건이 미충족이면 완료로 판단하지 않고 사용자에게 범위 선택을 요청합니다.

## 성능 문제의 국소 방어 예시

| 확인된 문제 | 현재 책임 내에서 검토할 수단 | 보존할 계약 |
| --- | --- | --- |
| N+1 조회 | 조회 전용 View/Projection, 필요한 관계의 선택 조회, 배치 조회 | 결과/정렬/페이징과 JPA Entity의 역할 |
| 메모리 버스트 | 제한된 페이지/청크 처리, 필요할 때 스트리밍과 자원 닫기 | 결과 누락/중복, 처리 순서, 메모리 한도 |
| 캐시 최신성/조회 비용 | 기존 직접 조회, 범위가 확인된 캐시 및 최소 무효화 | 데이터 최신성, 메모리 상한, 키/갱신 계약 |
| 장시간 트랜잭션 | 원자성을 보존하는 범위에서 외부 호출/계산을 분리 | 함께 성공/실패할 쓰기, 잠금과 롤백 조건 |

**필수 제어 예시:** 중복 재고 차감을 막아야 하는 기능은 첫 구현에서 원자적 조건부 갱신/버전 검사/필요한 행 잠금 중 유효한 수단을 포함합니다. 두 데이터 쓰기가 함께 성공/실패해야 하면 최소 트랜잭션 경계를 설정합니다. 여러 행에 걸친 규칙은 실제 격리/락 동작과 불변식을 검증합니다. 모든 수단을 중첩 적용하는 방식으로 시작하지 않습니다.

성능 문제라고 해도 요청된 데이터 처리 자체가 메모리 부족으로 실패하거나 필수 지연 한도를 초과한다면 구현의 필수 계약입니다. 이 경우 주석만 남기고 완료로 처리하지 않습니다.
