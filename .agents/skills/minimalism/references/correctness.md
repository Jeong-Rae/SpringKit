# 정확성 (COR)

작게 구현하는 과정에서 호출자 계약과 안전성을 유지할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COR-01 | 빈 값, 잘못된 값, 실패 시 호출자는 어떻게 복구하는가? | 입력 경계와 복구 가능한 오류 계약을 유지합니다. |
| COR-02 | 변경이 권한·기밀성·데이터 보존에 영향을 주는가? | 필수 검증과 부작용의 원자성을 보호합니다. |
| COR-03 | 실제 사용량과 동시 실행에서 실패하는 경로가 있는가? | 예상 부하의 경쟁·메모리·쿼리 비용을 검토합니다. |
| COR-04 | 위험한 로직이 잘못되면 어떤 검증이 실패하는가? | 회귀를 감지할 집중된 테스트를 남깁니다. |

## 실행 지침

- **COR-01:** 신뢰 경계에서는 입력을 검증하고, 도메인 불변식은 해당 책임 객체에서 보장합니다. 빈 입력, 경계값, 누락값, 시간·금액 계산과 실패 경로를 확인합니다. 예외는 내부 구현이 아니라 호출자의 복구 전략을 기준으로 구분합니다.
- **COR-02:** 인증·인가·입력 검사·비밀정보 보호·데이터 쓰기의 순서와 트랜잭션을 생략하지 않습니다. 이미 존재하던 오류 처리와 검증은 이동·통합 후에도 유지합니다.
- **COR-03:** 저장소의 사용 방식과 배포 구성을 통해 부하를 확인합니다. 다중 실행 시 경쟁 상태, 무제한 증가, N+1 조회, 대량 입력에서 비정상적으로 커지는 비용을 관련 작업에서만 점검합니다. 근거 없는 미래 규모를 위해 새 분산 계층을 만들지 않습니다.
- **COR-04:** 새 분기·파서·상태 전이·금전·보안·데이터 쓰기·버그 수정에는 실패 조건을 확인하는 최소한의 자동 테스트나 동등한 자체 검증을 추가합니다. 단순 형식 변경에 관성적으로 테스트를 늘리지 않습니다.

## Fixing의 사실 확인 (COR-01, COR-04)

문제가 발생한 입력, 기대 결과, 실제 결과, 재현 여부를 구분합니다. 테스트가 통과했다는 사실과 특정 원인이 밝혀졌다는 판단은 별개로 취급합니다. 호출 관계와 데이터 이동을 확인해 실제 책임 위치를 추적합니다.

원인을 아직 확인하지 못했다면 검증되지 않은 가설을 사실로 표현하지 않습니다. 원인 조사를 위한 범위를 클로저 후보로 제안할 수 있으며, 확인된 코드 경로와 조사 대상을 근거로 표시합니다.
