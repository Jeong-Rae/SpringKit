# 재사용 (REU)

Editing에서 구현 수단을 선택할 때 적용합니다. Fixing에서 클로저를 선택한 이후에도 같은 순서로 탐색합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| REU-01 | 저장소에 요구된 행동을 이미 제공하는 객체가 있는가? | 기존 객체의 공개 행위를 우선 직접 재사용합니다. |
| REU-02 | 기존 객체의 책임에서 필요한 차이를 수용할 수 있는가? | 기존 행위를 수정하거나 최소 변환/Adapter/Decorator로 조합합니다. |
| REU-03 | 프로젝트에서 사용할 수 있는 표준/플랫폼/설치된 기능이 있는가? | 이미 제공되는 기능과 프로젝트의 공개 계약을 활용합니다. |
| REU-04 | 신규 라이브러리가 필요한 기능을 제공하는가? | 도입과 직접 구현의 실제 유지/검증 비용을 확인합니다. |

## 규칙 실행 계약

### REU-01 - 기존 행위 직접 재사용

- **적용 조건:** Editing에서 구현 수단을 탐색하기 시작합니다.
- **수행 행동:** 관련 구현을 검색하고 기존 객체의 공개 행위로 요구된 동작을 구성합니다. 객체 내부 데이터에 대한 연쇄 접근이나 동일 책임의 서비스 중복을 피합니다.
- **판단 증거:** 기존 공개 API, 주변 호출 패턴, 수용 조건과 실제 반환/부작용 계약의 일치.
- **다음 전이:** 현재 계약으로 요구를 충족하면 `SIM`과 `COR` 검증으로 진행합니다. 확인된 계약 차이가 있으면 `REU-02`를 적용합니다.

### REU-02 - 기존 책임 수정 또는 최소 적응

- **적용 조건:** 기존 행위가 필요한 책임을 소유하지만 현재 요구와의 계약 차이가 확인됩니다.
- **수행 행동:** 기존 객체가 해당 행위의 책임을 소유하면 행위 수정을 검토합니다. 입력/출력 인터페이스 차이는 최소 변환 함수 또는 Adapter로 연결하고, 기존 계약을 유지하며 부가 행동을 결합할 때는 Decorator를 검토합니다. 단순 위임만 남는 래퍼는 도입하지 않습니다.
- **판단 증거:** 기존 객체의 책임, 현재 계약과 필요한 계약의 차이, 수정이 영향을 주는 호출자와 공개 경계.
- **다음 전이:** 수정/적응으로 필수 계약을 충족하면 해당 범위에서 구현합니다. 현재 책임과 계약으로 충족할 수 없으면 `REU-03`으로 진행합니다.

### REU-03 - 이미 제공되는 표준/설치 기능

- **적용 조건:** 기존 구현의 직접 사용/수정/적응으로 요구를 충족할 방법을 확인하지 못했습니다.
- **수행 행동:** 표준 라이브러리와 플랫폼 기능, 이미 설치된 의존성을 확인합니다. 프로젝트에서 관련 기능을 공개 컴포넌트로 감쌌다면 그 공개 계약과 주변 관례를 따릅니다.
- **판단 증거:** 프로젝트 의존성/지원 환경, 표준 기능의 계약, 해당 기능의 기존 사용처.
- **다음 전이:** 유효한 해법을 찾으면 구현과 검증으로 진행합니다. 없으면 `REU-04`에서 새 라이브러리 도입을 판단합니다.

### REU-04 - 신규 라이브러리 판단

- **적용 조건:** 앞선 후보로 필수 요구를 충족하지 못했고, 도입 가능한 새 라이브러리 또는 최소 신규 구현이 존재합니다.
- **수행 행동:** 실제 요구를 제공하는지 확인하고 보안 업데이트/지원 환경/라이선스/검증/운영 비용을 확인합니다. 검증된 전문 구현이 필요한 기능은 직접 구현 대체 가능성을 신중히 확인합니다.
- **판단 증거:** 공식 API와 지원 범위, 프로젝트의 버전/라이선스 제약, 해당 기능을 직접 작성할 때 필요한 책임과 테스트 범위.
- **다음 전이:** 요구와 제약을 충족하는 방법을 선택해 구현합니다. 현재 요구로 정당화되는 최소 신규 구현도 후보에 포함합니다.

## 적용 예시: 날짜 조회의 계약 차이

기존 조회 행위가 `String` 날짜를 받고 새 호출자가 날짜 객체를 전달한다면, 현재 입력 형식과 필요한 형식의 차이를 확인합니다. 기존 조회 책임을 유지하면서 변환 함수로 연결할 수 있으면 `REU-02`에서 탐색을 종료합니다. 기존 조회 로직은 재사용합니다.
