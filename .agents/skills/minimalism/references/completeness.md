# 완결성 (COM)

작은 변경이 실제 사용 경로 전체에서 완성되었는지 판단할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COM-01 | 바뀐 계약을 사용하는 모든 경로가 유지되는가? | 호출자·테스트·설정·고정 데이터의 영향 범위를 반영합니다. |
| COM-02 | 현재 수정은 오류의 원인을 제거하는가? | 공유 원인에 한 번 적용하고 관련 경로를 확인합니다. |
| COM-03 | 무엇을 확인했고 무엇이 확인되지 않았는가? | 검증 범위와 잔여 위험을 사실대로 보고합니다. |

## 실행 지침

- **COM-01:** 수정 전에 변경 함수·계약의 호출자와 사용처를 검색합니다. 시그니처, 반환값, 직렬화, 설정, 내보내기, 테스트, 픽스처 및 문서의 영향을 확인하고 필요한 부분을 함께 수정합니다. 기존 호환성을 변경할 때는 영향받는 사용 경로를 명시합니다.
- **COM-02:** 버그 재현 조건과 실패 원인을 식별합니다. 여러 호출자에 임시 우회를 복사하지 않고 공유된 책임에서 문제를 수정합니다. 영향을 받는 다른 호출 경로도 확인합니다.
- **COM-03:** 변경 위험에 맞는 테스트와 프로젝트가 요구하는 검증을 실행합니다. 실행하지 못한 검증을 성공으로 표시하지 않습니다. 결과는 변경 내용, 확인 결과, 생략한 작업 또는 남은 위험 순으로 간결하게 전달합니다.

## 완료와 종료 판정 (COM-01, COM-03)

**완결 여부:** 요구된 동작과 경계 조건을 확인하고, 변경으로 영향을 받는 호출자·설정·테스트를 필요한 범위에서 처리합니다. 프로젝트가 요구하는 검증을 실행하며, 미실행 항목은 성공으로 표현하지 않습니다.

**종료 여부:** 모든 필수 조건을 충족했고 구체적으로 제거할 불필요한 복잡성이 없다면 추가 구현이나 주변 리팩터링을 중단합니다. 검증에 실패하거나 실제 계약이 깨졌다면 종료하지 않고 원인을 수정합니다.

완결성과 종료는 별도로 판단합니다. 기능이 동작하더라도 필수 검증을 생략했다면 완결하지 않았으며, 검증에 성공하더라도 현재 작업에 필요하지 않은 기능을 추가할 이유는 없습니다.
