# 완결성 (COM)

작은 변경이 실제 사용 경로 전체에서 완성되었는지 판단할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COM-01 | 바뀐 계약을 사용하는 모든 경로가 유지되는가? | 호출자·테스트·설정·고정 데이터의 영향 범위를 반영합니다. |
| COM-02 | 증상이 발생한 곳과 원인의 책임 위치는 어디인가? | 원인과 수정 책임을 조사하고 선택된 클로저 안에서 수정합니다. |
| COM-03 | 무엇을 확인했고 무엇이 확인되지 않았는가? | 검증 범위와 잔여 위험을 사실대로 보고합니다. |

## 실행 지침

- **COM-01:** 수정 전에 변경 함수·계약의 호출자와 사용처를 검색합니다. 시그니처, 반환값, 직렬화, 설정, 내보내기, 테스트, 픽스처 및 문서의 영향을 확인하고 필요한 부분을 함께 수정합니다. 기존 호환성을 변경할 때는 영향받는 사용 경로를 명시합니다.
- **COM-02:** 버그 재현 조건과 실패 원인 후보를 식별합니다. 증상이 표시된 코드와 계약의 책임 객체를 각각 추적합니다. 관련 호출 경로를 확인한 후 수정 책임별로 독립적인 작업 클로저를 제안합니다. 사용자가 선택한 클로저 안에서만 수정합니다.
- **COM-03:** 변경 위험에 맞는 테스트와 프로젝트가 요구하는 검증을 실행합니다. 실행하지 못한 검증을 성공으로 표시하지 않습니다. 결과는 변경 내용, 확인 결과, 생략한 작업 또는 남은 위험 순으로 간결하게 전달합니다.

## 완료와 종료 판정 (COM-01, COM-03)

**완결 여부:** 요구된 동작과 경계 조건을 확인하고, 변경으로 영향을 받는 호출자·설정·테스트를 필요한 범위에서 처리합니다. 프로젝트가 요구하는 검증을 실행하며, 미실행 항목은 성공으로 표현하지 않습니다.

**종료 여부:** 모든 필수 조건을 충족했고 구체적으로 제거할 불필요한 복잡성이 없다면 추가 구현이나 주변 리팩터링을 중단합니다. 검증에 실패하거나 실제 계약이 깨졌다면 종료하지 않고 원인을 수정합니다.

완결성과 종료는 별도로 판단합니다. 기능이 동작하더라도 필수 검증을 생략했다면 완결하지 않았으며, 검증에 성공하더라도 현재 작업에 필요하지 않은 기능을 추가할 이유는 없습니다.

## Fixing의 작업 클로저 (COM-01, COM-02)

**작업 클로저**는 하나의 책임 경계와 그 변경을 검증하는 데 필요한 호출자·테스트·설정을 포함하는 수정 단위입니다. 증상이 발생한 파일과 원인의 책임 객체가 다를 때는 각각의 경계를 조사합니다. 실제 코드와 실행 증거가 있는 수정 위치만 제안합니다. 확인한 클로저가 하나라면 하나만 제시합니다.

제안은 **사용자가 수정 범위를 선택하기 전에** 제시해야 합니다. 사용자가 선택하기 전에는 Fixing 코드를 수정하지 않습니다. 이미 명시적으로 선택한 범위가 있다면 해당 선택을 존중합니다. 선택 범위 외의 변경이 필요해진 경우 새로운 클로저를 제안합니다.

### 제안 형식 (COM-02)

각 클로저를 아래 두 항목으로만 작성합니다.

- **제안:** 변경할 책임, 행위, 파일 또는 계층, 함께 수정할 검증 범위를 식별합니다.
- **제안의 근거:** 직접 확인한 코드 위치·호출 관계·입출력·실패 테스트·로그를 기술합니다. 원인 확인 여부가 불분명한 내용은 확정 사실로 작성하지 않습니다.

제안 단계에서 장단점, 트레이드오프, 우선순위, 가치 판단과 미래 결과 예측을 추가하지 않습니다. 사용자가 평가를 별도로 요청할 때만 그 평가를 수행합니다. 감정적 표현이나 암시적인 긍정·부정 표현 대신 확인된 코드와 실행 사실을 기술합니다.

가상의 코드 관계에 대한 제안 예시:

**클로저: API 응답 변환**

- **제안:** `OrderController`의 응답 금액 변환 행위를 수정합니다.
- **제안의 근거:** `OrderController`가 `OrderPrice`에서 받은 금액에 반올림을 적용하여 응답 값을 구성합니다.

**클로저: 도메인 금액 계산**

- **제안:** `OrderPrice`의 금액 계산 행위와 관련 테스트를 수정합니다.
- **제안의 근거:** `OrderController`와 `SettlementService`는 `OrderPrice`의 금액 계산 행위를 호출합니다.

실제 작업에서는 예시의 이름을 재사용하지 않고 저장소에서 확인한 코드 경로와 검증 결과를 근거로 작성합니다.

## Fixing 선택 이후의 완료 (COM-01, COM-03)

사용자가 클로저를 선택한 후에는 그 경계 안에서 Editing의 점진적 확장 탐색을 수행합니다. 변경 및 검증 결과에서 확인한 사실과 미실행 검증을 구분합니다. 추가 책임의 변경이 필요하면 해당 수정 범위를 새로운 제안으로 제시한 후 사용자 선택을 받습니다.
