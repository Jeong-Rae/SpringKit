# 완결성 (COM)

선택한 구현 범위가 사용 경로 전체에서 완결되었는지 확인하고 검증 결과를 전달할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COM-01 | 선택한 책임의 변경과 연결된 모든 사용 경로가 유지되는가? | 호출자/테스트/설정/고정 데이터까지 필요한 변경을 완결합니다. |
| COM-02 | 무엇을 확인했고 무엇을 확인하지 못했는가? | 수행한 검증 결과와 미확인 사항을 사실대로 보고합니다. |

## 규칙 실행 계약

### COM-01 - 변경 범위 완결

- **적용 조건:** Editing의 구현 범위를 정하거나 Fixing에서 사용자가 클로저를 선택한 후 변경/검증 범위를 확인합니다.
- **수행 행동:** 변경 함수/계약의 호출자와 사용처를 확인하고 시그니처/반환값/직렬화/설정/내보내기/테스트/픽스처/문서에서 필요한 변경을 반영합니다. Fixing에서는 선택된 클로저를 작업 경계로 유지합니다.
- **판단 증거:** 실제 호출 관계, 관련 설정/테스트 위치, 변경한 계약의 영향 경로와 검증 결과.
- **다음 전이:** 필요한 사용 경로가 유지되면 완료 판정으로 진행합니다. Fixing에서 추가 책임의 변경이 필요하면 `LOC-02`로 돌아가 사용자 선택을 받습니다.

### COM-02 - 완료 사실 보고

- **적용 조건:** Editing 또는 Fixing의 구현/검증 단계가 종료되거나 검증에 한계가 발생했습니다.
- **수행 행동:** 변경한 내용, 실제로 수행한 검증/부작용 결과, 미실행/미확인 항목과 보류한 **확인된 성능 문제**를 구분하여 전달합니다. 기능/정합성/필수 성능 조건이 미충족이라면 완료로 선언하지 않습니다. Fixing의 **클로저 제안 단계**에서는 `LOC-02`의 `제안`/`제안의 근거` 형식을 사용합니다.
- **판단 증거:** 검증 명령과 종료 상태, 테스트의 실제 결과, 검증하지 못한 경로의 목록.
- **다음 전이:** 모든 필수 수용 조건이 확인되면 작업을 종료합니다. 실패가 확인되면 원인이 되는 후보 판단으로 돌아갑니다. 검증을 수행할 수 없었다면 미검증 상태를 명시합니다.

## 완결과 종료의 구분

**완결:** 요구된 동작과 경계 조건을 충족하고 변경으로 영향을 받는 호출자/설정/테스트를 필요한 범위에서 처리했는지 확인합니다. 프로젝트의 필수 검증이 실행되지 않았다면 그 상태를 그대로 보고합니다.

**종료:** 완결을 확인하고 추가 구현을 요구하는 실제 조건이 없다면 종료합니다. Fixing에서 선택되지 않은 책임을 변경해야 한다면 새 클로저를 제안하고 사용자 선택 후 해당 범위에서 작업합니다.
