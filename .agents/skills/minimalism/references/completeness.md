# 완결성 (COM)

선택된 구현 범위가 실제 사용 경로에서 완결되었는지 판단하고 검증 결과를 전달할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| COM-01 | 선택한 책임의 변경과 연결된 모든 사용 경로가 유지되는가? | 호출자·테스트·설정·고정 데이터까지 필요한 변경을 완결합니다. |
| COM-02 | 무엇을 확인했고 무엇을 확인하지 못했는가? | 수행한 검증 결과와 미확인 사항을 사실대로 보고합니다. |

## 실행 지침

- **COM-01:** 변경 함수·계약을 사용하는 호출자와 사용처를 조사합니다. 시그니처, 반환값, 직렬화, 설정, 내보내기, 테스트, 픽스처·문서의 영향을 확인하고 필요한 부분을 함께 변경합니다. Fixing에서는 사용자가 선택한 클로저를 실행 경계로 삼으며, 새로운 책임 범위가 필요해지면 `LOC-02`에 따라 다시 제안합니다.
- **COM-02:** 변경 위험에 맞는 테스트와 프로젝트가 요구하는 검증을 실행합니다. 실행한 검증과 미실행 검증을 분리하여 보고합니다. 결과는 수행한 변경, 확인한 사실, 미확인 항목을 간결하게 전달합니다. Fixing의 **클로저 제안 단계**에는 이 결과 보고 형식을 적용하지 않고 `LOC-02`의 두 항목 계약을 사용합니다.

## 완료와 종료 판정 (COM-01, COM-02)

**완결:** 요구된 동작과 경계 조건이 충족되고, 필요한 호출자·설정·테스트가 처리되었는지 확인합니다. 검증이 실행되지 않았다면 그 상태를 명확히 남깁니다.

**종료:** 수용 조건과 필수 계약을 충족했으며 추가 구현을 요구하는 확인된 조건이 없다면 종료합니다. 검증에 실패했다면 실패 조건을 근거로 Editing의 탐색을 재개합니다. Fixing에서 선택되지 않은 책임의 변경이 필요해졌다면 새로운 클로저를 제안하고 사용자 선택 후 수행합니다.
