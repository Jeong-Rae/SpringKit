# 단순성 (SIM)

Rich Domain Model의 기존 책임과 시스템 동작을 유지하면서 구조/응답 분기/설정의 이해와 변경 비용을 최소화합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| SIM-01 | 이 객체의 구분을 정당화하는 실제 도메인 개념/불변식이 있는가? | 확인된 책임에 상태와 행위를 모으고 근거 없는 분리를 보류합니다. |
| SIM-02 | 새로운 패턴/아키텍처/예외 계층에 필요한 계약이 있는가? | 현재 요구와 프로젝트 관례에서 정당화된 개념만 도입합니다. |
| SIM-03 | 각 상태/응답 분기를 호출자가 실제로 구별하고 처리해야 하는가? | 필요한 분기만 구현하며 기존 실패 계약을 보존합니다. |
| SIM-04 | 코드의 동작과 이유를 따라갈 수 있는가? | 명확한 이름/배치/필요한 이유 설명을 유지합니다. |

## 규칙 실행 계약

### SIM-01 - 확인된 도메인 개념의 책임

- **적용 조건:** 기존 행위를 수정하거나 새 Entity/Value Object/Domain Service/Aggregate, 별도 책임 객체의 도입/분리를 검토합니다.
- **수행 행동:** 기존 Rich Domain Model에서 상태와 행위를 함께 가진 객체를 우선 활용합니다. 식별성/값 의미/불변식/독립 행위 등 **실제 도메인 개념**이 확인될 때만 책임을 분리합니다. 현재 도메인 의미가 아직 확인되지 않은 데이터를 새 도메인 타입으로 격상하지 않습니다. 조회 전용 View/Projection은 도메인 모델과 구분합니다.
- **판단 증거:** 프로젝트 유비쿼터스 언어, 사용자 요구, 기존 도메인 객체의 행위/불변식, 해당 행위의 호출 관계.
- **다음 전이:** 기존 책임 안에서 동작이 성립하면 그 행위를 수정합니다. 별도 도메인 책임이 확인되면 해당 경계만 구현하고 `SIM-02`를 확인합니다.

### SIM-02 - 패턴/아키텍처 도입 제한

- **적용 조건:** 새 인터페이스, 계층, 전역 예외 핸들러/오류 계층, 디자인 패턴, 아키텍처 구성요소 또는 설정을 도입하려고 합니다.
- **수행 행동:** 각 구성요소가 충족하는 현재 계약과 기존 프로젝트 규칙을 확인합니다. 확인되지 않은 Factory/Strategy/CQRS/Saga/이벤트 버스/예외 관리 체계나 전달 전용 래퍼는 도입하지 않습니다. 이미 확립된 경계는 유지합니다. Adapter/Decorator도 실제 인터페이스 차이와 부가 행위에 맞춰 사용합니다.
- **판단 증거:** 새 객체의 독립 책임/호출자/계약 차이, 저장소 관례, 현재 요구로 확인된 사용 사례.
- **다음 전이:** 현재 계약으로 정당화되는 최소 구성만 구현합니다. 해당 책임이 기존 객체에 있으면 재사용 후보로 돌아갑니다. 선택 범위를 넘는 재설계가 필요하면 `LOC-02`의 제안 경계를 적용합니다.

### SIM-03 - 상태/응답 분기 최소화

- **적용 조건:** 상태 전이, 조건 분기, API 응답/오류 분기를 새로 만들거나 변경합니다.
- **수행 행동:** 실제 도메인 상태와 호출자가 구분하여 복구할 실패 조건만 표현합니다. 현재 응답 계약으로 충분하면 새로운 결과 타입/오류 코드/예외 경로를 추가하지 않습니다. 반복 분기/상태 모델은 실제 규칙 중복이나 불변식에 대한 근거가 있을 때만 변경합니다.
- **판단 증거:** 기존 공개 API/오류 계약, 호출자의 복구 행동, 명시된 상태 전이와 실제 테스트 사례.
- **다음 전이:** 요구된 동작을 표현하는 최소 분기로 구현하고 `COR-01`의 호출자 계약을 검증합니다.

### SIM-04 - 코드와 설명의 가독성

- **적용 조건:** 코드를 작성/수정하거나 배치/명명을 변경합니다.
- **수행 행동:** 책임과 행위가 드러나는 이름 및 관련 코드의 근접 배치를 유지합니다. 코드에서 드러나지 않는 이유와 제약만 주석으로 남기고 프로젝트 포매터를 따릅니다.
- **판단 증거:** 객체 책임과 이름의 대응, 행위와 불변식의 배치, 주석이 설명하는 실제 제약.
- **다음 전이:** 책임과 동작을 읽고 검증할 수 있으면 해당 `COR` 규칙으로 진행합니다.

## 적용 예시

- **도메인:** 기존 `Order`가 취소 규칙과 상태 전이를 소유한다면 그 행위를 수정합니다. 새로운 `OrderCancellationPolicy`/`OrderCancellationResult`는 독립 도메인 책임이 확인될 때만 도입합니다.
- **조회 최적화:** N+1을 방어하기 위한 `OrderSummaryView`는 읽기 전용 데이터 표현으로 사용할 수 있습니다. 이를 새 Entity나 Aggregate로 취급하지 않습니다.
- **응답:** 호출자가 기존 오류 계약으로 충분히 복구할 수 있다면 별도 예외 계층과 세분화한 응답 상태를 만들지 않습니다.

Fixing의 책임 위치와 사용자 제안은 [원인/클로저](location.md)의 `LOC-01`/`LOC-02`에 따릅니다.
