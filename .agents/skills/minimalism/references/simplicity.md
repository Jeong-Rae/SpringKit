# 단순성 (SIM)

현재 요구를 구현하는 책임과 코드의 이해/변경 비용을 판단할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| SIM-01 | 필요한 행동과 상태가 올바른 책임에 모여 있는가? | 도메인 행위와 상태의 응집도를 유지합니다. |
| SIM-02 | 현재 요구로 정당화할 수 없는 추상화/설정/변환이 있는가? | 근거 없는 추가 계층과 우회 코드를 만들지 않습니다. |
| SIM-03 | 분기와 상태가 실제로 복잡해졌는가? | 이해/변경 비용이 줄어드는 경우에만 대안 표현을 도입합니다. |
| SIM-04 | 코드의 동작과 이유를 따라갈 수 있는가? | 명확한 이름/배치/필요한 이유 설명을 유지합니다. |

## 규칙 실행 계약

### SIM-01 - 책임과 응집도

- **적용 조건:** 기존 책임을 수정하거나 새 행위/상태/객체의 위치를 선택합니다.
- **수행 행동:** 함께 변경되는 상태와 행위를 해당 도메인 책임에 배치합니다. 기존 객체/계층의 협력 경계를 보존하고 서로 다른 책임만 분리합니다.
- **판단 증거:** 기존 도메인 행위와 불변식, 해당 행위를 사용하는 호출 관계, 함께 변경되는 상태와 규칙.
- **다음 전이:** 책임이 정해지면 `SIM-02`와 현재 구현 후보를 확인합니다. 기존 계층/객체의 책임이 확인되지 않으면 관련 사용 경로를 조사합니다.

### SIM-02 - 불필요한 개념 제거

- **적용 조건:** Editing의 후보를 판단하거나 새 타입/인터페이스/설정/변환/래퍼를 도입하려고 합니다.
- **수행 행동:** 각 새 개념이 충족할 현재 계약이나 책임을 확인합니다. 실제 경계나 행위 없이 전달만 수행하는 추상화/래퍼를 생략합니다. 이미 확립된 프로젝트의 경계는 유지합니다.
- **판단 증거:** 새 구성요소의 호출자/행동/계약 차이, 기존 공개 API와 프로젝트 관례.
- **다음 전이:** 새 개념이 현재 요구로 정당화되면 해당 책임을 구현합니다. 기존 구성요소로 충족할 수 있으면 재사용 후보로 돌아갑니다.

### SIM-03 - 분기/상태 모델 선택

- **적용 조건:** 반복 분기, 중복된 매핑, 다수의 상태 전이가 실제 변경 대상에 있습니다.
- **수행 행동:** 현재 분기와 데이터 테이블/상태 모델의 표현을 비교합니다. 규칙 중복과 상태 전이의 표현이 명확해지는 경우에만 대안을 선택합니다.
- **판단 증거:** 분기 수와 중복되는 규칙, 실제 상태/전이, 각 표현에서 수정해야 할 위치와 불변식.
- **다음 전이:** 책임을 보존하는 표현을 선택해 구현합니다. 현재 분기로 충분하면 그대로 유지하고 검증합니다.

### SIM-04 - 코드와 설명의 가독성

- **적용 조건:** 코드를 작성/수정하거나 기존 코드의 배치와 명명을 변경합니다.
- **수행 행동:** 의미가 드러나는 이름과 관련 코드의 근접 배치를 유지합니다. 코드에서 드러나지 않는 이유와 제약을 주석으로 남기고 포맷은 프로젝트 포매터에 맡깁니다.
- **판단 증거:** 변경된 책임과 이름의 대응, 관련 행위의 배치, 주석이 설명하는 실제 제약.
- **다음 전이:** 현재 책임과 동작을 읽고 검증할 수 있으면 `COR`의 관련 검증으로 진행합니다.

## 복잡성 판단 예시

수용 조건과 필수 계약을 충족한 후보만 비교합니다. 새로 이해해야 할 책임과 개념, 상태/분기, 의존성/결합도, 변경/검증 비용을 살핍니다. 코드 줄 수와 파일 수는 보조 지표입니다. 처음 찾은 유효한 해법을 기본으로 하되 다른 해법이 이 비용을 실질적으로 줄인다는 근거가 있을 때만 탐색을 계속합니다.

예: 읽기 어려운 한 줄 조건식을 의미 있는 두 함수로 나누어 책임과 실패 조건을 명확히 표현할 수 있습니다. 반대로 단순 전달만 하는 중간 인터페이스는 현재 계약에서 별도의 책임이 확인될 때만 도입합니다.

Fixing에서 원인/수정 책임 위치를 탐색하는 방법과 클로저 제안은 [원인/클로저](location.md)의 `LOC-01`/`LOC-02`를 따릅니다.
