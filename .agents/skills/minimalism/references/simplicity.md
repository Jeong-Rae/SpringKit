# 단순성 (SIM)

현재 요구를 구현하는 책임과 코드의 이해·변경 비용을 판단할 때 적용합니다.

## 규칙 코드표

| 코드 | 점검 질문 | 지시 |
| --- | --- | --- |
| SIM-01 | 필요한 행동과 상태가 올바른 책임에 모여 있는가? | 도메인 행위와 상태의 응집도를 유지합니다. |
| SIM-02 | 현재 요구로 정당화할 수 없는 추상화·설정·변환이 있는가? | 근거 없는 추가 계층과 우회 코드를 만들지 않습니다. |
| SIM-03 | 분기와 상태가 실제로 복잡해졌는가? | 이해·변경 비용이 줄어드는 경우에만 대안 표현을 도입합니다. |
| SIM-04 | 코드의 동작과 이유를 따라갈 수 있는가? | 명확한 이름·배치·필요한 이유 설명을 유지합니다. |

## 실행 지침

- **SIM-01:** 함께 변경되는 상태와 행위를 같은 책임에 둡니다. 기존 객체·계층의 협력 경계를 존중합니다. 서로 다른 책임은 분리하되 파일이나 함수의 줄 수만 줄이기 위한 분할은 하지 않습니다.
- **SIM-02:** 현재 책임과 계약이 뒷받침하지 않는 인터페이스·팩토리·Adapter·옵션·설정을 추가하지 않습니다. 이미 정해진 프로젝트 경계는 보존합니다. 위임과 값 전달만 수행하는 래퍼를 추가해야 한다면 실제 계약 차이를 확인합니다.
- **SIM-03:** 반복적인 분기 매핑에는 데이터 테이블을, 명확한 상태 전이가 많은 경우에는 상태 모델을 검토합니다. 대안이 중복 규칙·분기·수정 범위를 줄인다는 사실이 있을 때 선택합니다. 현재 분기가 단순하다면 그대로 유지합니다.
- **SIM-04:** 의미가 드러나는 이름과 관련 코드의 근접 배치를 우선합니다. 읽기 어려운 한 줄 표현을 피합니다. 코드 자체가 표현하지 못하는 이유와 제약만 주석으로 남기고 포맷은 프로젝트 포매터를 따릅니다.

## 복잡성 비교 (SIM-01~04)

수용 조건과 필수 제약을 충족하는 후보끼리 비교합니다. 새로 이해해야 할 책임과 약속, 상태·분기 수, 의존성·결합도, 검증과 수정에 필요한 비용을 확인합니다. 코드 줄 수는 이 조건을 충족한 후보 사이의 보조 지표입니다.

첫 번째 유효한 후보를 기본으로 선택합니다. 다른 후보가 책임·결합도·이해 비용을 실질적으로 줄인다는 근거가 있다면 추가 비교합니다. Fixing의 수정 책임 위치 선정과 클로저 제안은 [원인·클로저](location.md)가 담당합니다.

예: 읽기 어려운 한 줄 조건식을 두 개의 의미 있는 함수로 표현해 책임과 실패 조건이 분명해진다면 줄 수가 늘어나도 단순한 해법입니다. 반대로 현재 호출자의 역할 변화 없이 전달만 하는 인터페이스는 별도의 근거가 필요합니다.
