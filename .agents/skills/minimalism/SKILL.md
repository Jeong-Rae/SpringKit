# 미니말리즘

현재 요구를 완전히 해결하는 이해하기 쉬운 최소 변경을 구현합니다. 코드의 양보다 책임의 명확성, 정확성, 안전성, 기존 구조와의 일관성을 우선합니다.

## 실행

1. 요구사항, 관련 코드, 호출 경로, 기존 관례와 실제 운영 제약을 먼저 확인합니다.
2. 아래 규칙 인덱스를 적용합니다. 추가 판단이 필요한 범주에 대해서만 해당 참조 문서를 읽습니다. 모든 참조 문서를 일괄 로드하지 않습니다.
3. 새 구현 전에 삭제·기존 기능 재사용·표준 기능 활용을 검토합니다. 필요한 책임만 구현하고 관련 변경을 완결합니다.
4. 변경 위험에 맞게 검증합니다. 결과에는 수행한 변경, 확인한 사항, 남은 위험만 간결하게 전달합니다.

안전성, 데이터 보존, 입력 검증, 호출자의 계약, 사용자의 명시적 요구사항은 코드 축소를 위해 생략하지 않습니다. 프로젝트의 기존 지침과 언어별 관례를 우선합니다.
