# 기술 문서 작성 기준

이 문서는 SpringKit 기술 문서에만 적용합니다. 저장소의 필수 계약을 먼저
따르고, 아래 형식 기준과 내용 원칙을 차례로 적용합니다.

## 형식

- 강조는 필요한 단어나 문장의 첫 언급에 제한적으로 사용합니다.
- 코드, 명령, 데이터 타입, 속성, 파일 경로, 코드 식별자는 고정폭 글꼴로
  표시합니다.
- 화면의 메뉴와 버튼은 `[이름]`으로 표시하고, 이동 경로는 `>`로
  연결합니다.
- 링크 문구에는 `여기` 대신 대상 문서나 페이지의 구체적인 이름을
  사용합니다.
- 서술형 문장은 `-니다`로 마칩니다. 행동 지침에는 `합니다` 또는
  `해야 합니다`를 사용합니다.
- 목록과 표는 의미가 분명한 개조식 문장으로 작성합니다.
- 숫자는 아라비아 숫자로 쓰고, 4자리 이상은 세 자리마다 쉼표를
  사용합니다. 날짜와 시간 단위는 한국어로 씁니다.
- 예시는 `예:`로, 추가 자료나 출처는 `참고:`로 구분합니다.

## 용어

- 자연스러운 한국어 표현이 있으면 외래어나 영문 용어보다 우선합니다.
- 플랫폼, 프로그래밍 언어, 제품명처럼 번역하면 부정확한 고유명사는
  원문을 유지합니다.
- 외래어나 약어는 필요할 때 최초 언급에서 원문 또는 풀어쓴 명칭을 함께
  설명하고, 이후에는 한 가지 표현을 일관되게 사용합니다.
- 독자에게 낯설 수 있는 전문 용어는 짧게 뜻을 설명하고 신뢰할 수 있는
  참고 자료를 연결합니다.

## 내용

- 독자가 지금 알아야 할 핵심 메시지를 먼저 제시합니다.
- 한 문장에는 가능한 한 하나의 메시지만 담습니다.
- 의미를 바꾸지 않는 수식어와 같은 내용을 반복하는 문장 또는 절을
  삭제합니다.
- 작성자만 아는 배경을 전제하지 않고, 독자의 지식수준에 맞는 쉬운
  표현을 사용합니다.
- 절차에서는 다음 단계와 실행 결과를 예상할 수 있게 설명합니다.
- 선택지를 설명할 때 특정 행동을 강요하거나 불필요한 불안감을 만들지
  않습니다.
- 공감 표현은 독자의 상황을 이해하는 데 도움이 될 때만 사용하고,
  기술적 정확성을 흐리지 않습니다.

## 점검

- 제목과 첫 문장이 같은 내용을 반복하지 않는지 확인합니다.
- 각 문단이 하나의 핵심 메시지를 전달하는지 확인합니다.
- 불필요한 단어, 빈 문장, 중복된 절을 제거했는지 확인합니다.
- 코드, 화면 요소, 링크, 용어, 숫자와 날짜의 표기가 일관적인지
  확인합니다.
- 독자가 다음 행동과 예상 결과를 이해할 수 있는지 확인합니다.
