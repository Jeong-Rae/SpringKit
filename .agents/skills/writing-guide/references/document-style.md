# 기술 문서 작성 기준

한국어 기술 문서를 작성, 수정, 검토할 때 사용합니다. 특정 프로젝트나
제품에 종속되지 않는 기본값이며, 저장소나 사용자가 지정한 필수 형식이
있으면 해당 형식을 먼저 따릅니다.

## 글쓰기 원칙

### 다음 행동을 예상할 수 있게 씁니다

절차를 수행하면 무엇이 바뀌고 다음에 무엇을 할 수 있는지 설명합니다.

- Do: `[저장]을 선택하면 새 설정이 즉시 적용됩니다.`
- Not: `[저장]을 선택해 설정을 완료합니다.`

### 의미 없는 단어를 제거합니다

단어를 뺐을 때 의미가 같다면 삭제합니다.

- Do: `설정을 변경합니다.`
- Not: `이제부터 설정을 새롭게 변경합니다.`

### 빈 문장과 반복을 제거합니다

제목이나 앞 문장에서 전달한 내용을 장식용 문장으로 반복하지 않습니다.

- Do: `## 캐시 설정` 다음에 필요한 조건부터 설명합니다.
- Not: `이 절에서는 캐시 설정에 관해 설명합니다.`

### 핵심 메시지에 집중합니다

독자가 현재 판단하거나 실행하는 데 필요한 정보만 우선 제공합니다.

- Do: `요청 제한은 분당 100회입니다.`
- Not: `요청 제한에는 여러 배경이 있지만 여기서는 분당 100회를 안내합니다.`

### 말하듯 쉽게 씁니다

낯선 문어체와 긴 문장을 피하고, 한 문장에 하나의 메시지를 담습니다.

- Do: `토큰이 만료되면 다시 로그인해야 합니다.`
- Not: `토큰 만료가 발생하는 경우 재로그인이 요구되는 상황이 초래됩니다.`

### 강요하지 않고 안내합니다

선택권을 숨기거나 불필요한 불안감을 만들어 특정 행동을 유도하지 않습니다.

- Do: `알림을 끄면 중요한 변경 사항을 직접 확인해야 합니다.`
- Not: `중요한 정보를 놓치지 않으려면 반드시 알림을 켜야 합니다.`

### 누구나 이해할 수 있는 말을 씁니다

특정 조직의 은어, 유행어, 설명 없는 약어를 사용하지 않습니다.

- Do: `배포 전에 변경 사항을 함께 검토합니다.`
- Not: `배포 전에 싱크업해서 컨펌합니다.`

### 독자의 상황을 고려합니다

오류나 제약을 설명할 때 책임을 돌리지 말고 해결에 필요한 정보를 제공합니다.

- Do: `파일 형식이 지원되지 않습니다. PNG 또는 JPEG 파일을 선택합니다.`
- Not: `잘못된 파일을 선택했습니다.`

## 문서 형식

| 대상 | Do | Not |
| --- | --- | --- |
| 강조 | 핵심 상태를 `**빌드 성공**`처럼 제한적으로 강조 | 문장마다 굵은 글꼴 사용 |
| 이미지 내 문구 | 화면의 문구를 `**동의하고 계속**`처럼 표시 | 화면 문구와 설명을 같은 서식으로 표시 |
| UI 요소 | `[설정] > [카카오계정] > [연결된 서비스 관리]` | 메뉴와 버튼 이름을 일반 문장으로 표시 |
| 코드와 식별자 | `target_id`처럼 고정폭 글꼴로 표시 | 일반 글꼴로 target_id 표시 |
| 코드 블록 | 실행 가능한 명령을 언어가 지정된 코드 블록에 작성 | 명령과 설명을 같은 코드 블록에 작성 |
| 링크 | `[인증 설정 가이드](https://example.com/auth)` | `[여기](https://example.com/auth)` |
| 서술문 | `요청 결과는 JSON 형식입니다.` | `요청 결과는 JSON 형식임.` |
| 행동 지침 | `환경 변수를 설정해야 합니다.` | `환경 변수를 설정하십시오.` |
| 목록과 표 | `지원 버전: Java 21 이상` | `지원 버전은 Java 21 이상입니다.` |

코드 블록에서 생략한 부분은 공백 없는 온점 3개(`...`)로 표시하고, 설명은
코드 밖에 작성합니다. 코드 자체를 이해하는 데 필요한 설명만 주석으로
남깁니다.

문단, 표, 이미지처럼 위치가 바뀔 수 있는 요소는 `이전`이나 `다음` 대신
`위`나 `아래`로 지칭합니다.

## 용어

| 대상 | Do | Not |
| --- | --- | --- |
| 고유명사 | Android, iOS, Java, Kotlin, Flutter | 고유명사를 임의로 번역 |
| 외래어 최초 언급 | `메서드(Method)`, `파라미터(Parameter)`, `프로퍼티(Property)`, `리다이렉트(Redirect)` | 영문과 한글 표기 혼용 |
| 약어 최초 언급 | `APNs(Apple Push Notification service)`, `CLI(Command line interface)` | 설명 없이 약어 사용 |
| 전문 용어 | `SET(Security Event Token, 보안 이벤트 토큰)`과 [RFC8417](https://www.rfc-editor.org/rfc/rfc8417.html) 제시 | 독자가 이미 안다고 가정 |

자연스러운 한국어 표현이 있으면 우선 사용합니다. 번역하면 정확성이
떨어지는 플랫폼, 프로그래밍 언어, 제품명과 코드 식별자는 원문을
유지합니다. 최초 언급 이후에는 선택한 표현을 일관되게 사용합니다.

## 숫자, 날짜, 예시와 출처

- 숫자는 아라비아 숫자로 씁니다. 4자리 이상은 세 자리마다 쉼표를
  사용합니다. 예: `3,000,000건`
- 날짜와 시간 단위는 한국어로 씁니다. 예: `2023년 3월 28일 오후 2시 49분`
- 시간대나 데이터 형식이 중요하면 함께 씁니다. 예: `UTC 기준 RFC 3339 형식`
- 예시는 괄호나 별도 문단에서 `예:`로 구분합니다.
- 추가 자료와 출처는 구체적인 문서명에 링크하고 `참고:`로 구분합니다.

## 최종 점검

- 제목과 첫 문장이 같은 내용을 반복하지 않는지 확인합니다.
- 각 문단과 문장이 하나의 핵심 메시지를 전달하는지 확인합니다.
- 불필요한 단어, 빈 문장, 중복된 절을 제거했는지 확인합니다.
- 코드, UI 요소, 링크, 용어, 숫자와 날짜의 표기가 일관적인지 확인합니다.
- 독자가 다음 행동과 예상 결과를 이해할 수 있는지 확인합니다.
- 각 Not 예시에 해당하는 표현이 남아 있지 않은지 확인합니다.
