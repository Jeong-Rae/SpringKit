# Worker 요청

오케스트레이터의 대화 기록을 상속하지 않는 Worker가 혼자 이해할 수 있도록 요청을 완결된 형태로 작성합니다.

정확한 메시지 형식은 [Worker 요청 스키마](worker-request.schema.md)를 따릅니다.

## 필드 의미

### OBJECTIVE

논리적 커밋 전체가 달성해야 하는 동작 변화를 적습니다. 여러 Worker가 같은 목표를 공유할 수 있습니다.

### TASK ID

교섭, 후속 작업, 종료 보고를 같은 책임과 연결할 수 있도록 안정적인 식별자를 부여합니다.

### ASSIGNMENT

이 Worker가 맡는 구현 책임을 적습니다. 필요한 결과와 중요한 제약을 명확히 하되, 결과에 영향을 주지 않는 구현 세부사항은 미리 정하지 않습니다.

### WORKING DIRECTORY

Worker가 작업할 디렉터리를 적습니다.

### WORKING BRANCH

현재 공유 브랜치를 적습니다. Worker는 브랜치를 조회할 수 있지만 Skill의 Git 변경 제한을 따라야 합니다.

### PREPARATION

교섭 전에 읽어야 하는 저장소 자료와 이미 확정한 사실을 적습니다.

저장소에서 직접 확인할 수 있는 내용은 경로를 제시합니다. Known facts에는 오케스트레이터가 이미 결정했거나 확인한 사실만 적습니다.

### OWNERSHIP

수정할 수 있는 영역, 읽기 전용 의존 영역, 변경하지 않는 영역을 적습니다. 소유권은 실제 변경 파일을 예측하는 목록이 아니라 변경 권한의 경계입니다.

### ROLE

이 책임이 전체 목표에서 맡는 역할을 적습니다. 구체적인 작업 지시와 역할 설명을 구분합니다.

### REPORT CONTRACT

Worker가 따라야 하는 교섭 및 종료 보고 문서와 스키마를 지정합니다.
