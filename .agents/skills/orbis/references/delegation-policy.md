# 위임 정책

Worker 책임을 정하기 전에 이 정책을 적용합니다.

## 하나의 논리적 커밋을 유지합니다

오케스트레이션 범위는 하나의 논리적 커밋 안에 둡니다. 목표를 완결하는 데 필요한 변경은 포함하고, 독립적인 정리, 리팩터링, 후속 작업은 제외합니다.

Worker 작업이 시작된 뒤 새 책임을 발견하면 현재 커밋 클로저에 속하는지 판단합니다.

- 같은 논리적 커밋에 필요함: 책임을 추가하거나 조정하고 커밋 클로저를 계속 완성합니다.
- 독립적인 원자적 변경임: 현재 오케스트레이션에서 분리합니다.

처음 예상한 파일 목록으로 커밋 경계를 정하지 않습니다.

## 책임을 기준으로 위임합니다

각 Worker에는 하나의 응집된 구현 책임을 맡깁니다. 파일이 여러 개라는 이유만으로 책임을 나누지 않습니다.

하나의 책임을 함께 구현하고 검증할 수 있다면 한 Worker가 여러 구현 파일과 테스트 파일을 소유할 수 있습니다. 계약과 검증을 독립적으로 유지할 수 있을 때만 책임을 나눕니다.

오케스트레이터는 구현을 위임하고 목표, 의존 관계, 소유권, 커밋 클로저를 판단합니다.

## 소유권을 정합니다

각 책임에는 다음 범위를 정합니다.

- 수정할 수 있는 영역
- 읽기 전용 의존 영역
- 변경하지 않는 영역

동시에 수정하는 파일은 Worker 한 명만 소유합니다.

Worker는 구현이 쉬워진다는 이유로 소유권 밖의 파일을 변경하지 않습니다. 소유권 밖 변경이 필요하면 오케스트레이터가 범위를 다시 판단합니다.

## 의존 관계에 따라 순서를 정합니다

Worker 관계는 의존 그래프로 나타냅니다.

다음 조건을 모두 만족할 때만 같은 단계에서 병렬로 실행합니다.

```text
write(A) ∩ write(B) = ∅

write(A) ∩ requiredInput(B) = ∅

write(B) ∩ requiredInput(A) = ∅
```

한 Worker가 다른 Worker의 새 출력을 입력으로 써야 하면 순차로 실행합니다.

## 병렬 작업 전에 계약을 확정합니다

여러 Worker가 같은 인터페이스에 의존하면 현재 논리적 커밋에서 사용할 계약을 먼저 확정합니다.

인터페이스를 결정하거나 변경해야 하면 그 작업을 먼저 끝냅니다. 이후 Worker는 확정된 계약을 기준으로 실행합니다.

형제 Worker는 비정형 reasoning을 주고받으며 인터페이스를 정하지 않습니다.

## 통합 책임을 한 Worker에 둡니다

통합 코드와 공유 wiring은 Worker 한 명이 소유합니다. 기존 책임에 자연스럽게 포함되면 해당 Worker가 맡습니다. 별도 책임이면 선행 작업이 끝난 뒤 다른 Worker에 위임합니다.

오케스트레이터는 통합 코드를 직접 작성하지 않습니다.
