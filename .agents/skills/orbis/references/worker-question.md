# Worker 질의

Worker는 파일을 수정하기 전에 스스로 확정하기 어려운 사항을 오케스트레이터에게 질문합니다.

정확한 응답 형식은 [Worker 질의 스키마](worker-question.schema.md)를 따릅니다.

## 준비

질문하기 전에 다음 내용을 확인합니다.

- Worker 요청 전체를 읽습니다.
- PREPARATION에 지정된 자료를 모두 읽습니다.
- 적용되는 저장소 지침을 읽습니다.
- 관련 코드와 테스트를 필요한 만큼 확인합니다.
- 선언된 소유권 경계를 확인합니다.

저장소에서 직접 확인할 수 있는 사항은 질문하지 않습니다. 이 단계에서는 파일을 수정하지 않습니다.

## 질문 우선

Worker는 이해하기 어렵거나 스스로 확정하기 어려운 사항을 먼저 질문합니다.

질문 뒤에는 현재 이해한 내용과 질문 의도를 짧게 설명합니다. 오케스트레이터는 이 설명으로 Worker가 무엇을 알고 있으며 어떤 판단을 요청하는지 파악합니다.

한 번에 여러 판단을 요구하지 않습니다. 다음 작업을 결정하는 데 가장 먼저 필요한 질문부터 묻습니다.

## 상태

`QUESTION`은 오케스트레이터의 답이나 판단이 필요하다는 뜻입니다.

`READY`는 더 묻지 않아도 책임, 맥락, 계약, 소유권을 충분히 이해했다는 뜻입니다. `READY`는 쓰기 권한이 아니므로 `PROCEED`를 받을 때까지 기다립니다.

`OUT_OF_SCOPE`는 필요한 작업이 승인된 책임이나 소유권을 벗어난다는 뜻입니다.

`BLOCKED`는 책임을 이해했고 범위 안에도 있지만 실행 조건 때문에 진행할 수 없다는 뜻입니다.

## 질의응답

오케스트레이터는 질문에 답하거나, 잘못된 이해를 고치거나, 준비 정보를 보강하거나, 소유권과 책임을 조정합니다.

Worker는 답을 반영한 뒤 다시 판단합니다. 추가 질문이 있으면 `QUESTION`을 반환하고, 질문이 모두 해소되면 `READY`를 반환합니다.

ASSIGNMENT, PREPARATION, OWNERSHIP, CONTRACTS 가운데 중요한 내용이 바뀌면 Worker는 변경 내용을 다시 확인한 뒤 필요한 질문을 이어갑니다.

## 실행

오케스트레이터는 Worker가 `READY`를 반환한 뒤에만 `PROCEED`를 보냅니다.

Worker는 `PROCEED`를 받은 뒤 승인된 책임과 소유권 안에서 구현, 테스트, 자체 검토를 진행합니다. 구현 중 새로 확정하기 어려운 사항이 생기면 안전한 지점에서 멈추고 필요한 상태로 보고합니다.
