# PR 본문 작성 지침

PR 본문에는 개발 과정을 나열하기보다 리뷰어가 변경 사항을 검토하고 결정하는 데 필요한 내용을 씁니다. 꼭 넣거나 빼야 할 내용과 예외 규칙은 [pr-reviewer-guide.md](pr-reviewer-guide.md)에 정리되어 있습니다. 본문을 작성하거나 수정하기 전에 해당 문서를 읽습니다.

## 변경 내용 설명

무엇이 왜 바뀌고 어떤 영향을 주는지 먼저 설명합니다. 구현이 복잡하다면 주요 구성 요소의 책임과 협력, 선택한 설계의 트레이드오프를 설명합니다. 설명은 현재 변경 내용(Diff)과 맞아야 합니다.

## 검토 대상 명시

리뷰어가 확인할 계약, 실패 조건과 처리 경계, 가정 또는 설계 결정을 구체적으로 적습니다. 관련 설계 문서, 명세 또는 코드는 설명하는 위치에 연결합니다. 변경이 많고 검토에 도움이 된다면 파일이나 기능의 검토 순서를 안내합니다.

변경된 동작을 글보다 정확하게 전달할 수 있다면 Mermaid 다이어그램, 표 또는 스크린샷을 활용합니다. 시각 자료가 실제 구현과 일치하는지도 확인합니다.

## 일반적인 완료 기록 대신 예외 설명

Diff만으로 알기 어려운 중요한 동작을 검증으로 확인했다면 그 결과를 설명합니다. 검사가 실패했거나 검사를 생략해 리뷰어의 판단이 제한된다면 그 사실과 영향을 설명합니다. 명령어나 테스트 개수를 나열하지 말고, 확인한 계약과 그 근거 및 영향을 설명합니다.

마이그레이션, 단계적 배포나 롤백에 필요한 조건, 호환성 위험, 알려진 제외 범위가 리뷰나 배포 판단에 영향을 준다면 설명합니다. 내용이 없는 섹션과 일반적인 점검 목록은 추가하지 않습니다.

## 기본 구성

제목과 본문은 저장소에서 요구하는 언어로 작성합니다. 모든 PR 본문에는 이 문서의 작성 원칙과 [pr-reviewer-guide.md](pr-reviewer-guide.md)의 Must / Must Not 규칙을 적용합니다. 대상 저장소에 적용 가능한 PR 템플릿이 있다면 아래 기본 구성 대신 해당 템플릿을 사용하고, 템플릿의 추가 작성 요건도 충족합니다. 필수 섹션과 질문은 유지합니다. 템플릿의 요구 사항과 일반 작성 지침이 충돌하면 템플릿을 우선합니다. 충돌하지 않는 규칙은 계속 적용합니다. Should 권고도 검토합니다.

적용 가능한 저장소 템플릿이 없을 때만 아래의 한국어 제목을 사용합니다. 쓸 내용이 없는 섹션은 생략합니다.

```markdown
## 변경 내용

<목적, 변경된 동작, 핵심 구현 구조와 설계 근거>

## 검토할 사항

- <검토할 구체적인 계약·경계와 참고 링크>

## 남은 범위와 제약

- <리뷰 판단에 영향을 주는 실제 제약 또는 미검증 사항>
```

본문은 변경 규모에 맞게 필요한 만큼만 씁니다. PR 제목, 푸터, 브랜치 및 게시 절차에는 저장소의 필수 규칙을 우선 적용합니다.
