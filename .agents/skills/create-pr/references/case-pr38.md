# SpringKit PR #38: 주제별로 나누고 그림으로 설명하기

사례: [Agent Guidebook BC/Slice 리팩터링](https://github.com/Jeong-Rae/SpringKit/pull/38). 2026년 11월 6일 확인한 PR 본문과 최종 Diff를 바탕으로 설명을 다시 구성한 예시입니다. 확인하지 않은 변경 이유나 테스트 성공 여부는 덧붙이지 않습니다.

## 기존 설명의 문제

- 첫 문단부터 `BC`, `Slice`, `domain`, `search`, `provision`이 등장합니다. 기존 구조가 실제로 어떤 실패나 비용을 유발했는지는 설명하지 않습니다.
- 다음 문단에 Port, Repository, UnitOfWork, SQLite, Codex, Factory, Application이 모여 있습니다. 독자는 어느 요소가 무엇을 맡고 의존하는지 직접 추론해야 합니다.
- 공개 API 호환성 중단, DB 이력 단절 같은 중요한 변경이 패키지 배치 설명보다 뒤에 있습니다.
- 변경 파일 149개 중 기술 문서 16개가 삭제됐습니다. 기존 계약이 다른 문서나 코드에 남아 있는지 확인해야 합니다.
- CI 비활성화는 밝히지만, PR 본문만으로 로컬 테스트의 실행 결과를 판정하기 어렵습니다.

## 권장 시작 단락

`Agent Guidebook`의 검색/지침 제공 기능이 여러 패키지에 분산되어 있습니다. 이번 PR에서는 하나의 Bounded Context 안에 `search`와 `provision`을 구분하고, 공통 검색 규칙은 `domain`으로 옮겨 책임 경계를 재구성합니다. **기존 호출 API와 SQLite 이력에 대한 호환성은 제공하지 않습니다.**

기존 패키지 구성이 실제로 어떤 유지보수 문제를 일으켰는지는 확인되지 않았습니다. 근거가 확보되면 시작 문단에 추가합니다.

## 권장 서브헤딩

### 도메인과 기능별 책임

`domain`, `search`, `provision`이 각각 맡는 일을 설명하고 변경 전후의 책임을 표로 비교합니다. `search`와 `provision`을 분리한 실제 이유를 덧붙입니다.

### Slice 간 협력과 기술 구현

`provision`과 `SearchGuidelines`의 의존 관계, 파일 시스템과 SQLite Adapter를 조립하는 Factory의 위치를 실제 코드에서 확인한 뒤 Mermaid로 나타냅니다.

### 공개 API와 실행 진입점

기존 호출 방법과 새 호출 방법을 간단한 표로 비교합니다. 기존 소스 코드 및 바이너리와 호환되지 않는다는 점을 명확히 알립니다.

### 이력 저장의 변경과 데이터 영향

Exposed에 트랜잭션을 맡긴 이유, 이력 저장 테이블을 `provision`으로 바꾼 점, 기존 이력을 재사용하지 않고 마이그레이션을 제공하지 않는 점을 각각 설명합니다. 실제 지침 제공 동작에 미칠 위험과 이를 수용한 근거는 따로 검토해야 합니다.

### 검증 범위와 삭제한 문서

변경된 테스트가 무엇을 확인하도록 작성되었는지와 **실제로 실행에 성공했는지**를 구분합니다. 삭제된 계약/검증 문서 중 현재 유효한 계약이 코드/테스트/README에 남았는지 점검합니다. CI가 비활성화됐다는 사실도 설명합니다.

### 검토 요청

리뷰어가 책임 경계, 호환성 중단, 기존 DB 이력 처리, 트랜잭션과 동시성 경계를 확인할 수 있도록 검토 항목을 작성합니다.

## 이 예시의 교훈

검토할 주제에 따라 문단을 나눕니다. 복잡한 관계는 표나 다이어그램으로 보여 주고, 무엇이 달라졌는지 설명합니다. 설계 선택의 이유와 위험도 빠뜨리지 않습니다.
