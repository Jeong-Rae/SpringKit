# 리뷰어 중심 PR 평가 기준

각 항목을 `0`~`2`점으로 따로 평가합니다. **총점은 참고용**입니다. 중요한 계약이나 위험이 빠졌거나 검증 결과를 잘못 적어 `FAIL`로 판정한 항목은 총점이 높아도 수정합니다. PR의 규모와 위험을 고려해 점수를 매깁니다.

| 축 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 문제와 필요성 | 문제/목적 불명 | 일반적 목적만 설명 | 구체적 기존 문제/변경 필요성 제시 |
| 의미 있는 변화/범위 | 주요 계약 누락 | 변화 목록은 있으나 영향 연결 부족 | 중요한 변경과 보존 계약을 모두 설명 |
| 선택의 근거 | 큰 설계 변경인데 이유 없음 | 이유는 있으나 비용/대안 불명 | 주요 선택/이유/대가를 판단 가능 |
| 검증의 정확성 | 허위 또는 과장 | 실행 명령/테스트 존재만 제시 | 실제 결과와 보장 범위/미확인을 구분 |
| 위험과 리뷰 결정 | 중요 위험 누락 | 위험은 있으나 질문 불명 | 주요 위험과 검토할 선택을 제시 |
| **내용 구성과 찾기 쉬운 정도** | 중요한 정보가 장문에 묻힘 | 서브헤딩이 있으나 의미/관계가 혼재 | 핵심 선행, 의미별 구획, 필요한 표/관계도와 쉬운 탐색 |

총점은 12점입니다. 10~12점은 우수 후보, 7~9점은 일부 보완, 0~6점은 문서 구조를 다시 검토할 대상으로 봅니다. 점수 구간은 이 Skill의 내부 기준이며 업계 표준은 아닙니다.

## 중요 위반 판정

- 중요한 계약 변경 누락 (`PRC-004`), 중요 위험 은폐 (`PRC-007`), 검증의 허위/과장 (`PRC-006`/`PRC-008`)에서 `FAIL`이 나오면 점수와 무관하게 **수정 필요**.
- PR이 읽기 어려운 경우 (`PRC-010`~`PRC-013`) 원인에 맞춰 구조를 고치되, 도표가 없다는 사실만으로 `FAIL` 판정하지 않습니다.
- 확인하지 못한 사항은 `NEEDS_REVIEW`로 표시하고 추정으로 점수를 높이지 않습니다.
- 과거형, `Agent`라는 단어, 테스트 명령어만으로는 위반이라고 판단하지 않습니다.

## 평가할 때 남길 정보

`[문제 ID] [판정] [원문 위치/근거 Diff] [리뷰어에게 미치는 영향] [수정 방향] [수정 후 근거]`.

예: `PRC-010 | FAIL | 변경 내용의 두 문단 | 책임 변화와 사용자 영향, 검증 범위가 한 문단에 섞여 판단할 내용을 찾기 어려움 | 의미별 문단 구분 | 수정 후 중요 계약과 위험, 검증 범위 위치 재확인`.

예: `PRC-012 | NOT_APPLICABLE | 오탈자 수정 하나 | 관계 설명이 없고 한 문장으로 이해 가능 | 그림 불필요 | 변경 범위와 일치`.
